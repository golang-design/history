Go 1.1

Part II · commits first contained in tag go1.1 ^go1 (tagged 2013-05-13) · 967 in-scope commits

Per-P scheduler with local run queues. Runtime-integrated network poller. Parallel GC and the first precise heap scanning. 8-entry-bucket hashmap with incremental growth, plus AES hash. Race detector. External (host) linking. int is 64 bits on amd64. Method values.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Memory management: GC and allocator (Go 1.0–1.17)

Parallel GC with parfor and per-thread work buffers, and the first precise heap scanning from type information; "Stop-the-world mark-sweep…", "Precise heap scanning", "Mark work distribution".

  • Stop-the-world mark-sweep, then the parallel collector — Done: parfor-based parallel GC (d839a809b2, 342658bbb6, 95643647ae, b0702bd0db, d4c80d19a8, 2924638d26 replaces a lock with casp); sweep batch free (4945fc8e40); zeroing moved out of the heap mutex and skipped for huge blocks (c1c851bbe8); GC stats (cea46387b9) and the stop-the-world time shown separately in GOGCTRACE (fd32ac4bae); user-visible runtime/debug GC controls (472354f81e). Left open: marking depends on conservative scanning of stacks and untyped blocks (see precise-GC thread).
  • Precise heap scanning: type information, the heap bitmap and GC programs — Done: precise heap scanning from types (9204eb4d3c, 059fed3dfb, 92c153d5f4, 6e69df6102, 21ea5103a41.2 in 1.2), unions→structs (cfe336770b, 60682c4f59), 709e03f43d disable hook, type-info checker (bd1cd1ddea). Left open: stack scanning and parts of runtime data stayed conservative.
  • Size classes, tiny allocator and mcache/mcentral — Done: zero-size coalescing (ec59b840f9), faster mcentral (d8626ef128), earlier detection of unused spans (09ea3b518e), scavenged spans needing zeroing (9ad236ab72), distinct pattern marking free blocks needing zeroing (c80f5b9bf7). Left open: nothing noted.
  • Scavenger: returning memory to the OS — Done: scavenged spans marked as needing zeroing (9ad236ab72). Left open: nothing noted.
  • Heap address space: contiguous arena to sparse arenas — Done: run-time metadata allocation (8a6ff3ab34), 128 GB (9799a5a4fd), no PROT_EXEC on heap mmaps (5a8b7dc6d0), runtime.memlimit ignored when allocating heap (515353a290). Left open: nothing noted.
  • Finalizers and span specials — Done: special bit not unset after finalization (348087877c), finalizer root address preserved (e5dae3baaa), runfinq frame hidden from GC (e9bbe3a8da). Left open: nothing noted.
  • Mark work distribution: parfor, work buffers, gcWork and root jobs — Done: parfor and per-thread work buffers (95643647ae, d4c80d19a8), addroot optimisation (ab08eac5b7), strings marked without a buffer (ec8caf696a). Left open: nothing noted.
  • Memory statistics and accounting — Done: per-M GC stats (d839a809b2), cea46387b9, uintptr malloc stats (0b09425b5c, 09f48db3e1), memorydump() (e0c9d04aec). Left open: nothing noted.

Scheduler and concurrency

From Scheduler and concurrency runtime (Go 1.0–1.17)

  • Channels and select — Done: precise GC of channels a656f82071; heapsort select lock order cb32ea9c19.
  • Semaphores, runtime locks and Notes — Done: lock-free stack a5dc7793c0, semaphore table hidden from GC 35724c1aa5, double-wakeup diagnosis 4380fa6d99; unions → structs for Lock and Note d617454379, 58030c541b.

  • sync.Map, atomic.Value and sync/atomic — Done: Linux/ARM 64-bit atomics 090f9fc3ef, unaligned detection 14a295c817, 94b7853924; FreeBSD/NetBSD ARM ace9ff4578, 4d8b1feb79; race instrumentation 59b8745328, 27087022ce, f3c1070fa41.2.
  • Goroutine and M lifecycle: caches, ids, LockOSThread, Goexit, cgo extra Ms, deadlock detection — Done: 64-bit goids 320df44f04; Gosched for locked Gs f87b7f67b2; checkdead false negative 06a488fa97; locked bit cleared 1a4599b41a; park refactor f20fd87384.

From Runtime data structures and type metadata (Go 1.0–1.17)

The 8-slot bucket hashmap with incremental growth and fast-path routines, AES hash, reflect.MakeFunc/Select/Convert/Of and method values, the removal of run-time code generation, ARM softfloat conditional execution and faster ARM division.
