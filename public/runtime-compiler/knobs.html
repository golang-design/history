GOEXPERIMENT lifecycles

GOEXPERIMENT flags are how most large runtime and compiler changes were staged. Each one goes from added (off by default, opt-in), to default-on (added to the baseline in internal/buildcfg/exp.go, so you opt out with GOEXPERIMENT=noX), to flag removed (the old code path is deleted). This table was derived by diffing src/internal/goexperiment/flags.go and the baseline set in internal/buildcfg/exp.go at every cycle boundary. Each transition is attributed to the cycle in which its commit landed on master.

Before 1.18: experiments as a table inside the toolchain

Before Go 1.17 there was no baseline. An experiment was an entry in a table compiled into the toolchain, and it was off unless GOEXPERIMENT named it when the toolchain was built. The table lived in src/cmd/gc/lex.c up to Go 1.4. For Go 1.5 it moved to src/cmd/internal/obj/go.go, and dba9eb3369 re-implemented GOEXPERIMENT in the runtime and liblink for the frame-pointer experiment. From Go 1.9 the table lived in src/cmd/internal/objabi/util.go. In Go 1.17, 6304b401e4 consolidated the experiments into internal/goexperiment, a8e55538af made GOEXPERIMENT a diff against per-platform defaults (the baseline used in the table above), and 5159c83641 added the active set to runtime.Version(). This table was derived by reading the experiment table at every release tag from go1 to go1.17. Each transition is attributed to the first release tag that contains its commit.
