Go 1.23

Part II · master 1653833811..c622f5c341 · 667 in-scope commits

Timer rewrite with GC-able synchronous timer channels. Range-over-func ships. unique and internal weak pointers. Linkname lockdown. v1 tracer deleted. Profile stack depth 128. First spinbit attempt (reverted). Stack-slot merging. GOARM64/GORISCV64.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Runtime: memory allocator and garbage collector (Go 1.18–1.28)

  • Soft memory limit and GC CPU limiter — Done: GC CPU pause accounting became exact. The pause update was factored out (08a7ab97ba) and uses maxprocs instead of stwprocs (ae0a08dee9). Pause time now starts when the world is actually stopped, removing overlap with idle time (d4395ebc0c), and the time Ps spend in _Pgcstop while stopping is added back individually (e995aa95cb). The limiter consumes these values. Left open: nothing noted.
  • Heap bitmap rewrite and allocation headers — Done: user-visible the experiment and old code were removed (9f3f4c64db). Headers made large pointerful zeroing preemptible (de3a3c9ebc, publication thread). Left open: nothing noted.
  • Finalizers, runtime.AddCleanup and the cleanup queue — Done: user-visible doc note on method receivers in SetFinalizer (f7c330eac7). Left open: nothing noted.
  • Weak pointers and the unique package — Done: user-visible internal/weak (dfc86e922c) and the unique package with Make/Handle (a088e230d4); string clone via stringslite (4dccb78582); HashTrieMap iteration (3a3837f422). Left open: the weak API was internal only.
  • Object pinning (runtime.Pinner) — Done: runtime.debugPinnerV1, a self-pinning Pinner for debuggers using debugCall (7f9edb4225). Left open: nothing noted.
  • Mark worker scheduling and GC work queues — Done: gcBgMarkStartWorkers uses channels instead of notes, so runnext can hand off directly (5dceddfe7c); data/bss root jobs computed in one loop (0b1b6c1589). Left open: nothing noted.
  • Allocation publication, zeroing and preemptibility — Done: preemptible zeroing of large pointerful objects (de3a3c9ebc). Left open: nothing noted.
  • Sweeper termination and pacing — Done: large-object stats updated before freeSpan, fixing /memory/classes/heap/unused underflow (36d32f68f4). Left open: nothing noted.

Other changes

  • allocfreetrace replaced by traceallocfree user-visible — GODEBUG=allocfreetrace removed (11047345f5). The traceallocfree experiment records alloc/free events in execution traces, with a batch carrying heap base and alignment for ID compression (724bab1505, efe7a1f5d3, ca1d2ead5d).
  • time.Timer no longer embeds runtime timer state internal — touches the scavenger’s timer use (bc20704c26).

Scheduler and concurrency

From Runtime: scheduler, timers, channels, locks and synchronization (Go 1.18–1.28)

  • Timer rewrite: per-P timer heap, timer.lock, and GC-able synchronous timer channels — Done: Cox’s stacked refactor, deliberately in tiny steps: delete addtimer/clearDeletedTimers (4a3c3ec996, 77f0bd01fb), merge statuses (b2bd7ebafc, 09bfea95cf, 3be36e9b20, ed0ad591d3, db8c6c8c7a), introduce timer.lock and use it in deltimer/modtimer/cleantimers/runtimer/adjusttimers/moveTimers (51df232b12, 2fb5ef889b, 58911599e8, d1e8dc25ff, 1df6db8e4f, c6888d9264) with a new lock rank (b5a99eaa94), status→state and method-ification (a155a2f8a1, 370c8e983b), per-P timers struct (adc575e64c; the message doubts the pair of atomic int64 deadlines hide missed wakeups), then the state cleanup above (6135651867). user-visible GC of unstopped timers (508bb17edd) and synchronous Stop/Reset (966609ad9e). Follow-ups: use of per-M/P timers needs acquirem before choosing ts (lost-sleep flake 2965dc9895), zombie count fixes (40cc3eb278, e38be310a4), timers.wakeTime race (85bbb12141), Ticker.Reset spurious race (24fa7544b0), adjust fast path (1c864333ca), avoiding netpoll wakeups at timer creation (84b190ad3c), cleanHead optimisation (97f1b76b4b), restoring the older adjust call order because it measured faster (77d9cb8937), timer race (fae6eb5f2f), heap sift simplification (d0051be847), debug tracing (38723f2b38). Left open: Stop/Reset racing a running timer returned wrong results.
  • Runtime mutex: tri-state futex/sema locks → “spinbit” mutex — Done: first attempt at futex lock redesign for profiling blame: share the sema lock2 structure with futex locks and double-link the waiting-M list (be0b569caa, d881ed6384, dfb7073bb8), plus unlock-time contention profiling (ba1c5b2c45, 8ab131fb12). All five commits reverted on 2024-05-29 (1be701a344, 5dead59add, afbbc2894b, 3f4be127bc, 9114c51521) because the patch series reduced the maximum throughput of contended runtime.mutex and regressed applications where that is the bottleneck. Left open: both a scalable lock and a correct blame-the-unlocker profile.
  • Contended runtime-lock profiling (mutex profile for runtime-internal locks) — Done: acquireLockRank always acquires the M so m.locks is consistent when deciding whether profiling is safe (4bb67bc21e). Unlock-blame attempt reverted (see spinbit thread). Left open: blame semantics.
  • Scheduler core: spinning Ms, work conservation, stealing, STW interaction — Done: idle-P race in injectglist (24070cf747); runnext disabled on wasm (no sysmon to prevent runnext ping-pong starvation) — added and reverted (0c64be46ac, a6a5c30d2b, 4afb155cdf); trace acquire/release across all P steals (c9d88ea2aa). Left open: nothing noted.
  • Coroutines (iter.Pull runtime support) — Done: thread-lock state is bound to the coro at first newcoro; full lock state (counts and locked thread) must remain identical thereafter; simple nested/serial iter.Pull stays fast while exotic cases fail (dfe781e1eb); goexit propagation from iterator in Pull (9d2aeae72d). Left open: restrictions “may consider lifting”.
  • sync package API evolution — Done: user-visible Map.Clear (5b6cd3d0cb, 3b0d39c5da). Left open: nothing noted.
  • sync/atomic and runtime atomics — Done: runtime atomics moved to internal/runtime/atomic (4c2b1e0feb); user-visible atomic.And/Or (192d65e46b). Left open: nothing noted.
  • Runtime lock ranking — Done: acquireLockRankAndM (4bb67bc21e); lockWithRankMayAcquire nosplit (3959d54c0b); sched/allp < timers rule removed (854dea060e). Left open: nothing noted.
  • Netpoller — Done: Windows websocket handling moved out of the runtime (d0dc93c8e1); netpoll event sources identifiable on Windows (1de46564a7). Left open: nothing noted.

Other changes

  • Trace/GC CPU pause metrics internal — d4395ebc0c, e995aa95cb; stack ownership check for traces (d6a3d093c3); frame pointer in syscalls (2b82a4f488, 6737f4cee5, and later 54fe0fd43f1.24).
  • Timer plumbing leftovers internal — 8a493a6672, 3ad5cd4741, c961ab3fe9, 3c39b2ed11, 7381123235, b2e9221089; sync cleanups (5bce5362da, 36cd880878).
  • Misc internal — pahole struct sizing (552faa8927); profstackdepth GODEBUG (66cc2b7ca7); pc buffers to M (2141315251); kq parameter (1c924572d0); Windows netpollBreak identification (29746b4814); mips And/Or (9623a3586f), linknames (6ec291f495); exithook safe for concurrent os.Exit (f85c40438f); casgstatus throws on systemstack (0304d035cd); crashFD init (3d20a327a1); dead code (be29a02161); legacy linkname documentation (1d3d6ae725, 05cbbf985f, 2a7ca156b8, 9a3ef86173); atomic Or doc (201129414f).

Data structures and type metadata

From Runtime: maps, built-in data structures, hashing, randomness and type metadata (Go 1.18–1.28)

  • Map hashing and hash functions (memhash, aeshash, fallback hash) — Done: the 64-bit fallback hash mix() first argument was attacker controllable (xor of input with constants) so zeroing the multiplier produced many collisions; it is now xored with the process seed (ef2f3391da), then constants xors removed/odd-forcing dropped (c260de24b6, 35c619398b). hashkey was deterministic because it was initialised before rand was seeded; now uses bootstrapRand (1a3682b4c1). memhash{32,64} lost their external linkname (2e9ed44d391.24, landed in the 1.24 cycle). Left open: nothing noted.
  • Compiler-generated equality/hash functions and type descriptor emission (reflectdata) — Done: itabs generated via the rttype mechanism (977803e796), compiler uses abi.MapMaxKeyBytes etc. (4605ce2d34), MaxPtrmaskBytes merged into internal/abi (ff4e45fbc2). Left open: nothing noted.
  • internal/abi type layout unification and type metadata (rtype → abi.Type) — Done: abi.ITab in reflect (f2db96cd6c), EmptyInterface/TypeOf/NoEscape (4742c52e10), zeroVal moved to internal/abi and then reverted back to runtime (2f5b420fb5, 4c589d93ad), ifaceIndir removed then restored “for now” (55a06f7920, 2064413b54). Left open: nothing noted.
  • Interface conversion: itabs, type switch and assertion caches — Done: compiler generates itabs with rttype (977803e796), 2589a89468. Left open: nothing noted.
  • reflect implementation: performance, allocation and escape behaviour — Done: user-visible reflect.SliceAt (d08a957298), Type.OverflowInt/Uint/Float/Complex (33013e8ea8), iteration methods Value.Seq/Seq2, Type.CanSeq/CanSeq2 (524a774634, b44600f83f), TypeFor faster for concrete types (2413629aa8), Comparable true for nil interface (e41fabd688), String kind in Pointer/UnsafePointer (3d61f24835), StructOf sets TFlagRegularMemory (99e12bee44) with an array fix (3330c69476), anonymous field name omitted from type string (2ff89341f6). Left open: nothing noted.
  • memmove / memclr / memequal / internal/bytealg assembly optimisation — Done: strings.Compare intrinsified through bytealg.CompareString→runtime_cmpstring, ~28% faster, because slices.SortFunc needs a three-way compare (fd999fda59); arm64 memequal short-circuits identical pointers (66b776b025: O(n)→O(1), geomean 43.5ns→2.4ns; all other arches already had it); wasm memchr result extension fix (90c6558b6a). Left open: nothing noted.
  • Slice growth, string building and allocation-free bytes/strings helpers — Done: Builder.Grow size classes (968b71bce4). Left open: nothing noted.
  • Runtime randomness: fastrand, chacha8rand and math/rand/v2 — Done: internal/byteorder use (8623c0ba95). Left open: nothing noted.
  • iter.Pull and range-over-func iterator types — Done: user-visible types Seq/Seq2 exposed without experiment (5a181c5042), double next/yield rejection (ff743ce862), panic propagation (1471978bac), Goexit propagation (9d2aeae72d), stop-before-next (1634fde4f9), doc from proposal (fe36ce669c). Left open: nothing noted.

Other changes

Diagnostics and knobs
