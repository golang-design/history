Go 1.25

Part II · master 9da530f11a..2696a11a97 · 650 in-scope commits

Green Tea GC experiment. Container-aware GOMAXPROCS. Flight recorder. Spinbit everywhere. DWARF 5. Core types gone from the checker. Unlocker-blame runtime-lock profiling. Allocation-free interface conversions of constants and composite literals.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Runtime: memory allocator and garbage collector (Go 1.18–1.28)

  • Soft memory limit and GC CPU limiter — Done: sched.idleTime was double-counted when the limiter forced an up-to-date flush; fixed (385000b004). Left open: nothing noted.
  • Green Tea: span-based marking with vector scan kernels — Done: user-visible the greenteagc GOEXPERIMENT was added, off by default (f1ebad19bd). Size-class tables moved into internal/runtime/gc so generators could share them (528bafa049, e90ba1d208). The core landed: scan bits, per-P span queue, global overflow list, and per-size-class stats under GODEBUG=gctrace=2 (1b40dbce1a). Supporting work: a faster inner-loop bit clear (b30fa1bcc4); setting mspan.limit before publication so the conservative scanner cannot index past allocBits (4c7567290c); allocation-time publication made safe against conservative scanning (24ea1aa25c, see the publication thread); per-P overhead cut from ~2.6 KiB to 536 bytes when the experiment is off (d4bf716793); an explicit nil check in spanInlineMarkBits.init to avoid read-faulting fresh pages to the zero page, which made hugo slower (f8ccda2e05); and word-at-a-time mark merging, ~33% faster, with clearing folded in and skipped for fresh spans (397d2117ec, 0c6296ab12, 6d4a91c7a5, 75a19dbcd7). Left open: “A future extension … is to use SIMD-accelerated scanning kernels” (1b40dbce1a); experiment off by default.
  • mallocgc decomposition and size-specialized malloc — Done: needzero removed from paths that must always zero (144d4e5d5f). Left open: nothing noted.
  • Finalizers, runtime.AddCleanup and the cleanup queue — Done: user-visible checkfinalizer (3df078fc74, 913c069819, eec8dd0836, c58f58b9f8, 8b45a3f78b, 5b0b4c01ba), with queue lengths printed each cycle (0d42cebacd); finalizer blocks cleaned up (57cd75a351); the multi-goroutine cleanup queue (e46c8e0558, 1421b982dc); a missed-wakeup fix by re-checking the full list after marking asleep (b450b5409d); nil-P skip in procresize (8dd7d2111b); race-detector annotations (3ea94ae446). sync, reflect and unique moved from SetFinalizer to AddCleanup (954e2c0b06, b4e992b6e1, 0028532118). Left open: c58f58b9f8 flagged that a tiny-allocated cleanup arg “could end up co-located with the object”; fixed in 1.26 (1bb1f2bf0c1.26).
  • Weak pointers and the unique package — Done: user-visible weak.Make accepts linker-allocated objects (6d7cb594b3); Pointer conversions between types are blocked (8163ea1458); equality semantics clarified (5ec76ae5aa); weak pointers work in sbrk mode (53b9eae387). The unique canon map with AddCleanup landed (0028532118, e382bf5b32, 2f036e1475, ca3b474702, 644905891f). Compiler help for unique.Make: no copy for string(b) (27ff0f249c) and modeled data flow of non-string pointers for escape analysis (5e6a868b28). Left open: “We still need some kind of back-pressure mechanism” for cleanups (0028532118).
  • Allocation publication, zeroing and preemptibility — Done: the fresh-from-OS zeroing skip restored plus atomic largeType (df9888ea4e); the freeIndexForScan snapshot (24ea1aa25c). Left open: nothing noted.
  • Sweeper termination and pacing — Done: goschedIfBusy in bgsweep to avoid a livelock once lock is inlined (e666f1dabf); gcpacertrace end-of-sweep condition (ad7a6f8159). Left open: nothing noted.
  • Stack and register root scanning — Done: GC STW now calls casGToWaitingForSuspendG, avoiding mutual deadlock with the tracer’s suspendG (c6ac736288). Left open: nothing noted.
  • Address-space layout, tagged pointers and the mem.go layer — Done: user-visible anonymous mappings named via PR_SET_VMA_ANON_NAME (e.g. [anon: Go: page summary]), Linux 5.17+ (52eaed6633). 512-byte tag alignment (9d0320de25, aix fixes 3009566a46, 0c15d88974); freebsd/amd64 to 57 bits for LA57 (5bbac667c5). Left open: nothing noted.
  • Linear-memory heaps (Wasm and sbrk platforms) — Done: missing unlock in sysReserveAlignedSbrk (456a90aa16). Left open: nothing noted.

Other changes

  • GODEBUG=gccheckmark=1 repaired internal — had bit-rotted (root jobs not reset, noscan in workbufs, arenas, preemption); a dist smoke test was added (b25b5f3ff4).
  • gQueue/gList carry their size internal — (e0dba45c62).
  • plan9 heap sampling internal — the floating-point-free nextSampleNoFP was deleted now that Plan 9 can use floating point (40c953cd46).

Scheduler and concurrency

From Runtime: scheduler, timers, channels, locks and synchronization (Go 1.18–1.28)

  • Timer rewrite: per-P timer heap, timer.lock, and GC-able synchronous timer channels — Done: bubbled timers behave like unbubbled ones: channel timers enter the bubble heap only when blocked on, and due timers run immediately rather than being queued, random order for same-instant timers (3432c68467, 3bd0eab96f); fake clock excludes monotonic time (5916bc5b57). Left open: nothing noted.
  • Runtime mutex: tri-state futex/sema locks → “spinbit” mutex — Done: committed to spinbit everywhere including emulated-Xchg8 platforms, tri-state implementations deleted; wasm excepted (single thread) (7a177114df). Left open: nothing noted.
  • Contended runtime-lock profiling (mutex profile for runtime-internal locks) — Done: unlocker blamed (4d0f955a5e); fix for cputicks overflow causing zero-duration events (ac645eaa0e). Left open: nothing noted.
  • Scheduler core: spinning Ms, work conservation, stealing, STW interaction — Done: only one P at a time polls the network in findRunnable (352dd2d932), reverted for a CockroachDB benchmark regression (489917fc40), reintroduced (1e436ba668); explicit exclusion of a theoretical globrunqget->runqput->runqputslow recursion by refactoring runq/globrunq APIs (a42e337ede, +size field for gQueue/gList e0dba45c62); semrelease no direct G handoff on systemstack (a189516d3a); allpSnapshot stashed on M (740857f529). Left open: nothing noted.
  • GOMAXPROCS container awareness and dynamic updates — Done: user-visible cgroup discovery and default-on behaviour (f12c66fbed, e6dacf91ff); rename to updateMaxProcsG (6160fa59b6); updatemaxprocs metric only when disabled (3b77085b40); guarantee of no GOMAXPROCS-update syscalls after a GOMAXPROCS call by synchronising with sysmon (for sandboxing) (e481a08e0e); custom GOMAXPROCS noted even when the value is unchanged (f069a82998). Left open: parent limits, cgroup migration (“we can consider changing this in the future”).
  • testing/synctest bubbles — Done: fake clock stops advancing once the main goroutine exits (d6c8bedc7b); no monotonic reading in bubbled time.Time (5916bc5b57); race-detector happens-before for AfterFunc (c0392e7e49); “bubble” terminology (ef7724c432); closing bubbled chans from outside panics (d596bc0e81); hchan.bubble pointer (0afcf9192c); WaitGroup association (b170c7e94c); cond-misuse fatal (21b7e60c6b); distinct deadlock message once the main goroutine is done (049a5e6036); lock rank for weak pointers vs synctest (b78e38065e); clearer bubbled stack traces (848a768ba7); timers aligned with unbubbled (3432c68467, 3bd0eab96f). Left open: some violations still recoverable panics.
  • Asynchronous preemption: extended register state — Done: arm64 resumes via return (77343fa646); internal/runtime explicitly excluded from async preempt (92a63bdfee). Left open: nothing noted.
  • sync package API evolution — Done: user-visible WaitGroup.Go (822031dffc), f must not panic (9921537a96); fewer allocations in OnceFunc family via single captured struct (c5ff26a7a0); funcs not kept alive after panic (ee0d03fab6); Once.done as atomic.Bool (95611c0eb4). Left open: panic handling in WaitGroup.Go.

Other changes

  • Panic printing internal — 478ad013f9.
  • Misc internal — schedtrace output (ecda82012d, 5295722238); m padding for 64-bit (b199d9766a, 3968a5bca4); isExtraInC (577bb3d0ce); linknames kept for sonic (279da96532); frame-pointer preamble (742fda9524); atomic types not to be copied (42d3cdc909); Map.Delete doc (583d586ef9); synctest linker-alloc WG (4f86f22671); wording/cleanup (d365f2266d, c3a0859720, 4ed9943b26).

Middle end and SSA optimizer

From Compiler: middle end and SSA optimization (Go 1.18–1.28)

  • Profile-guided optimization (PGO): hot-call inlining, devirtualization, profile preprocessing — Done: a zero-weight edge is never chosen as the hottest callee (13b1261175). Left open: nothing noted.
  • Inliner: budget, closures, and the interleaved inline/devirtualize driver — Done:
    • Infinite recursion and out-of-memory when inlining closures were fixed (34073a736a, 4f45b2b7e0).

    • ir.ContainsClosure was added (a08984bc8f), and CallExpr.NoInline was removed (3033ef0016).
    Left open: nothing noted.
  • Escape analysis: call modelling, closures, func-variable callees, and solver speed — Done:
    • The solver speedups 04a9b16f3d, 74304cda29 and f506ad2644.
    • Escape uses an ir.ReassignOracle (e89791983a).
    • unique.Make models the data flow of non-string pointers (5e6a868b28), and SSA eliminates the string copy in calls to unique.Make (27ff0f249c).
    • -m=2 logs became more accessible (8bf816ae68, c1aad08901).
    • The literal and constant allocation avoidance described in the next thread.
    Left open: nothing noted.
  • Allocation avoidance: stack-allocated slice backing stores and allocation-free literals — Done: user-visible fewer allocations.

    • Follow-ups preserve side effects when rewriting with literals (988a20c8c5), keep the optimization on under coverage (479b51ee1f), add literalallochash (e46d586edd), and fix line numbering (66536242fc).
    • Variable-sized makeslice is stack-allocated, pointer-free elements only (7a427143b6). Pointerful elements were then allowed (2d050e91a3), and static len/cap are resolved (ba3f568988).
    • append backing stores are stack-allocated, cmd/go <0.1% bigger (ce88e341b9).
    • variablemakehash and the threshold flag were added; they found the culprit in #73199 (2c9689ab0e). The optimization is off under -N (21acfdc4ef).
    • Stack buffers are over-aligned to match heap alignment (c8bf388bad).
    • In a related backend change, scalar heap allocations are aggregated (5fc596ebe7).

  • Prove pass and bounds-check elimination: from poset relations to a dense limit table, topo-sorted walk, and division-aware proofs — Done:

    • Type-based alias analysis (11f7ea8ce0, #70488).
    • memcombine handles different-size stores (113b25774e), with an offset fix (d6c29c7156).
    • Store-to-load forwarding works with copy-compatible types (16a6b71f18).
    Left open: nothing noted.
  • Loop variable per-iteration semantics (loopvar) — Done: an ICE in the transformation was fixed (a0dc7bf084). Left open: nothing noted.
