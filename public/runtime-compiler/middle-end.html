Design. The SSA backend started as cmd/internal/ssa and was moved to cmd/compile/internal/ssa. A function is a Func of Blocks holding Values; each Value has an Op, a Type, a numeric AuxInt, an Aux payload and Args. Generic ops are in gen/genericOps.go, machine ops in per-arch gen/*Ops.go; the opcode tables (opGen.go) are generated (0dca7351e9), and the rewrite functions (rewritegeneric.go, rewriteAMD64.go) are generated from .rules files by gen/rulegen. The front end (gc/ssa.go) converts the walked AST into SSA; a long list of “unimplemented” node kinds gated what could be compiled at first (083a646f63 first generated code from SSA by extracting an obj program, enough to run iterative Fibonacci).

Early on, the project was bootstrapped incrementally: 8c6abfeacb separated debug logging, work-in-progress (“Unimplemented”) and fatal errors, so SSA could be attempted on every function and the whole standard library became a compilation test; only functions named _ssa used the result. d298209b1c added GOSSAFUNC/GOSSAPKG to enable SSA code for one function or package without rebuilding, and 5844603f14 aggregated the “unimplemented” reasons (SLICEARR 14.85%, CALLINTER 13.84%, RETJMP 11.84%, EFACE 10.24% of failures at that moment) to prioritise work. 5b355a7907 replaced “compile everything, then decide” with deciding first and only sending chosen functions through SSA. 729abfa35c made the compiler tests default to SSA on amd64, after which the TODO was to remove the UnimplementedF machinery.

Two data-representation decisions shaped everything later. 2a5e6c47bc redefined sub-register integers: the high bits of a register holding a sub-word value are junk, so ops that consume sub-word args must use width-specific forms (x86 has them; indexing is the exception) and ops producing sub-word results need not extend; generic ops pretend register size equals type width. 7fc5621991 defined the representation of AuxInt as the sign-extended version of the low bits for every width, so (Const8 [0x1]) and (Const8 [0x101]) stop being distinct to CSE. Types moved out of the SSA package (85e0329fbc), ssa.Type lost Equal in favour of the cheaper back-end Compare (2563b6f9fe), and Store/Move/Zero ops later carried the stored type as Aux (211c8c9f1a).

Architectures were enabled one by one: amd64 by default in the 1.7 cycle, ARM (42181ad852, with -ssa=0 to disable), then in 1.8 arm64, mips64 and s390x (their enabling commits belong to the per-architecture backend slices) and ppc64 big-endian (eed061f89c); 7f033933ce added GOARCH=mips{,le} to gc.

Generic rewrite rules and rulegen

Span: Go 1.7 → Go 1.9 · Status at go1.17: still the design at go1.17 (rules in ssa/gen/*.rules, generated rewrite*.go; extended with new rule syntax and later machinery).

Continues in: Rewrite-rule generator, typed Aux/AuxInt, and rule syntax (Go 1.11 → Go 1.16)

Design. Machine-independent simplification lives in gen/generic.rules (with dec.rules for decomposition of strings, slices, interfaces, complex). A rule is (Op args) [cond] -> (result); rulegen parses the pattern, generates one Go function per top-level op (a347ab7cd1 split op rewrites into separate functions) wrapped in a for loop that restarts the match after a rewrite (0543447597), and the driver applyRewrite runs until fixed point. Pitfalls were detected mechanically: unbalanced rules (1807d54d85), rewrite loops of length >1 via Floyd’s cycle finder advancing 1.5 steps per cycle (baf2c3ec4a) and OpCopy loops (f421735bb4). Rulegen automatically copies values on the right-hand side (0fb818a424), can target a specific block (177b697ba5), logs the rule line number (514ab7c385, later behind a codegen flag f85faefa67) and emits a rule-coverage log (0e930015c1). The rules are typed: 606a11f464 detects the type earlier; 6a1153acb4 (1.8) factors out parseValue, makes op selection depend on the number of args so arch ops may share names with generic ops, and reports unresolved ambiguity. 69fe9ea43e (1.9) unified the generated-code header.

The rule set grew from basics (9b25da732b simplifications, 198fc9a9eb foldings) to constant folding and normalisation: comparisons with constants (cdc36252fe, d4a95e78fa), constant shifts (93a0b0f315, c8b148e7a5 for lsh/rsh/lsh), float constant folding (f6ceed2cab), modulo (060501dc0e, 68325b56e7 folds IsInBounds of modulo), IsInBounds with small index (9549c06ce6, bbd3ffbd83), Neg folding (964dda9bf1, 417f49a363), distributing multiplication over addition (1f6e9e36b0), AND x const as a shift (adc8d491c2), truncate-of-AND (97b2295f06), Trunc-of-Ext (5c3edc46a6), redundant extension after shift (ac74225dcc), logical identities (4d5adf1eb1), bool ops OrB/EqB/NeqB/AndB (8b92397bcd), boolean simplification (6a24b2d0c1, commutativity of boolean ops 9aeced650f), negation folded into comparison (00459f05e0), pointer rules (a7a199947a, 3294014ae1 OffPtr collapse, da1802f1df, 6ed10382f7 smarter isSamePtr), 64-bit division strength reduction (a3055af45e), floating point strength reduction x*2→x+x (63a72fd447), shift pairs to sign/zero extensions (72a071c1da), bit twiddling (00db0cbf86), canonicalising constants to one argument position and reassociating (379567aad1, which folds 4 + x - 1 and 4 & x & 1), constant pointer comparison (d68bb16b1e), Zero-after-newobject removal (b2e0e9688a, c8eaeb8cba), and store-elimination rules for values just loaded from the same location (4fc498d89a, up to 3 intermediate stores to disjoint fields). Common subexpression elimination (cse) and its scalability

Span: Go 1.7 → Go 1.9 · Status at go1.17: still the design at go1.17 (partition refinement by sorted argument classes).

Design. CSE partitions values into equivalence classes, then replaces each value by a dominating member of its class. The first form compared types via Type.Equal, with the type string forming the coarse initial partition (d9a704cd40), and did not combine Phis of different blocks (00437ebe73: an inner-loop i phi and a different block’s phi were merged, which deleted the increment and made the loop spin). Subsequent changes were driven by compile-time blowups on generated code:

  • initial partitions built by recursively comparing values and their arguments (b96189d1a0, ~3–5% on compilebench) and cached CSE keys (317226e61c, 8c954d5780, 851ceebceb, bc07922843, c3db6c95b6 “double speed”);
  • the dominator queries inside CSE were N^2 (2a29576562) and then replaced by a shared dominator tree (e0611b1664) and by sorting each class by dominance so that dominating values come first, removing a linear scan per substitution (3ea7cfabbb; issue 15112 from 1m26s to 52s);
  • the refinement itself was O(n^2) (pick one value, split into matching/non-matching) until 30088ac9a3 replaced it by sorting a class by the equivalence classes of its arguments and splitting at changes, O(n log n) and no longer needing cmpDepth; issue 15112 from 282s to 20s, issue 16361 from 8s to 3s. e6051de035 first lowered cmpDepth from 4 to 1 (issue 17127: 8 minutes to 1 minute) before that rewrite. Value semantics: commutative ops are normalised (88c1ef5b45, fixed by 6317f92f6e in 1.9), -0.0 and 0.0 are different (ce4317266c, and adba6c4fdf treats a -0.0 literal as 0.0 at SSA build), tuple selectors are copied/typed uniformly (3d5cf72ca9, 08dca4c649), constant strings can be CSE’d after reusing aux symbols (e22ba7f0fb), and a constant cache (62% hit rate over the stdlib) avoids creating duplicates (194c79c163, extended by 39214275d6 to nil/iface/slice/“” and by 3dcfce8d19 to OffPtr [c] SP, which alone had been ~30% of all CSE’d values).

Design docs & discussion
  • background Go Escape Analysis Flaws listed in Go: A Documentary

Design. esc.c (later esc.go) tags each parameter with an escape note (esc:$mask, in modern terms “leaking param”). It traces assignment paths from address-taken variables and pointer-typed variables to sinks, tracking loop depth (loopdepth) so that things assigned out of a loop level escape. Go 1.0 inherited a simplified recursion (42687d6ce4, 2011-08), spurious-leak fixes (0227c45ede), DOTMETH handling (f2460a8c57), better loop depth for labels (9bf3478658) and the -mm diagnostic sink (4e78818259).

For Go 1.1, the analysis was restructured. 9fe424737b runs it per call-graph SCC in dependency order (mutually recursive functions in one batch; before, a package was one batch). 75692424d2 and 507fcf37d2 (Luuk van Dijk) introduced flow of inputs to outputs: step 0 synthesised outparams, step 1 gave them loop depth 0, step 2 emitted esc:$mask tags but still tied any param with a nonzero mask to the sink, and the next step used tags in esccall so functions that merely return their argument no longer leak it. 2667dcd113 steals escape info when inlining wrapper functions (issue 5056), 2c4b029b75 (listed under Go 1.2) uses the escape result for make([]T, const) (issue 5484), 572d984eaa/ba97d52b85 fix variable-capture-in-loops bugs.

Correctness work in 1.3/1.4 mattered because stack copying made “stack pointer in the heap” a crash rather than a harmless leak (fe3c913443): functions returning an indirect of a parameter (func f(z **int) *int { return *z }) were tagged non-leaking; the fix marks parameters whose pointed-to content reaches a result as “content escapes to result” and at call sites forces all indirections of such an argument to the heap. The message states the trade-off: a more precise version would record which result and how many indirections; the less precise, the more heap allocations. eb592d8289 stopped following uintptr passed as arguments (aligned with the GC no longer seeing pointers in uintptrs; also makes syscall args non-escaping). e5d742fcad relaxes address-of analysis, c99dce2b05/f078711b41 fix ... and slice-of-array, 775ab8eeaa handles &x inside switch x := v.(type), f20e4d5ecb &result into result, and d2204e6c0e/337fe4134f forbid/diagnose escaping args in the runtime package.

Go 1.5 loosened it where safe: 22c16b4b92 ignores re-slicing assignments (b.buf = b.buf[n:m] made b escape; two stdlib cases, zip -6.5% allocs), 1b87f01239 links STRUCTLIT to PTRLIT so &T{...} element initialisers escape only when the literal does, a21cf5b6a2 makes slice literals (before append) non-escaping and tracks pointers in slices, b19ec6842d made indirect function and method calls leak everything (they previously didn’t), 66130907d1 handles copy, 878a86a129 fixed closures captured by value (issue 10353: new(int) captured by a heap closure stayed on the stack), 6f6bcadc17 adds ODOTTYPE to escwalk, 5d18282695 factors bottom-up visiting out for reuse (used by inlining), e5060c7f75 moves the “large type is heap allocated” check into the analysis. 1.6: variadic ... args stop always escaping because the summary was already computed (f7a39a54e9, issue 12006), 745cdc3ad7 repairs range &fixedArray, e779bfa5d2 models escape across loop levels: heap allocation is forced by address publication, unknown/large size, unknown multiplicity or reachability from heap; the bug was an object reachable from a heap closure (forced by multiplicity in a loop) not being propagated, so a newly discovered heap allocation now propagates by loop level.

1.7–1.9 added tooling and precision: 2d56dee61b adds escape explanations to -m -m (“experimental”; the author notes the graph poorly handles level adjustments and that a single flooded graph would be cleaner), bea5252a13 adds an explicit “where” to EscStep, d8c815d8b5 notes escape of parts of closure-captured vars, d603c27c6b makes large pointer literals escape, f1eed92fd0 (1.8) requires flood to run to a fixed point, 923a74ce77/83c73a85db ignore contentEscapes for marking nodes as escaping, f8a3444388 removes EscScope, in 1.9 1e29cd8c2b ignores dead code, a69754e30c unnamed parameters do not escape (issue 19687), 24e94766c0 special-cases reflect header fields, fcee3777fd moves addrescapes/moveToHeap into esc.go.

Prove pass: unsatisfiability, partial-order facts, loop bounds-check elimination

Span: Go 1.10 → Go 1.17 · Status at go1.17: still the design at go1.17 (facts table + poset, induction variables found inside prove); loop BCE merged into prove in 1.11 → continues as Prove pass and bounds-check elimination: from poset relations to a dense limit table, topo-sorted walk, and division-aware proofs (1.18+)

Earlier history: Prove pass and bounds-check elimination (Go 1.7 → Go 1.9)

Design docs & discussion
  • background Bounds Checking Elimination

Design. ssa/prove.go walks the dominator tree and keeps a factsTable of relations between SSA values for each domain (signed, unsigned, and later a per-value limit). Up to 1.10 the pass asked implication questions of the table (“does a dominating fact imply this branch’s condition?”). In 1.11 Austin Clements flipped this to unsatisfiability: branch conditions are only ever asserted, and if the table becomes contradictory the branch is dead and cut (669db2cef5). That removed factsTable.get, let derived facts (len/cap relations, fence-post implications 6436270dad, unsigned limits derived from signed ones 941fc129e2) be used regardless of the shape of the branch condition, and let the pass skip provably unreachable blocks.

The second big step was Giovanni Bajo’s 1.11 series. Loop bounds-check elimination, previously a separate loopbce pass that only told prove “a lie” about len(s)-delta bounds, was moved into prove: findIndVar is reused and the induction facts are registered when the loop block is entered (7ec25d0acf), and the old pass was deleted (f49369b67c). 5c40210987 added a transitive closure of relations through a new poset data structure (ssa/poset.go): a forest of DAGs over SSA values that records <, <=, ==, !=, detects contradictions, and “proved hundreds of conditions” in make.bash; e0d37a33ab taught it x+d < w for non-constant w and that len/cap are non-negative (633 more checks removed in std+cmd), and 3c8545c5f6/67656ba71b reduced allocations by reusing posets and improving undo. Poset development continued in 1.13/1.14: constants moved into the first DAG (490646e476), constants handled more flexibly (c3a871fde1), multiple aliases per pass (18d57bc892, 7e68f81dd8), path collapsing (c70e5475e6, which Bajo says will be fundamental when poset is used for numerical limits), a debugging mode and integrity checker (19532d04bf, 0a5116493c), inequality recording changed (90888ed97b), and a fix to use only sufficient conditions for OrderedOrEqual (3c56eb4083).

From 1.13 on contributors (mostly zdjones) taught prove about the shapes that real code produces: facts flow through value-preserving sign/zero extensions (69ff0ba798), the index is learned to be >= 0 after a successful bounds check (2d41444ad0, 92 checks removed), non-negativity comes from the poset (ddef157813), facts from OpSliceMake (87e2b34f7b), induction variables bound by other induction variables (1658263bbf) and unrolled loops (d8f60eea64), isNonNegative handles more ops (ea3bfba87c, 5fac45a320), right shifts of positive ints by width-1 become zero (2cb10d42b7), and transitive slice len/cap relations in poset (5e804ba17d, 1.17). Prove also feeds later passes: shifts are marked bounded from its bounds (9eb4590ad2, stored in AuxInt by 743fd9171f) and Ctz non-zero proofs are logged (b9785fc844).

Escape analysis: the esc.go fixes, the escape.go rewrite, and the move to package escape

Design. Through 1.12 escape analysis was the 2000-line AST-walking esc.go, which handled the various ways values flow with a fixed-point over EscState and encoded parameter leaks in a small bit-field. Its 1.10–1.12 history is a series of precision and correctness fixes (loop depth of range expressions dbb1d198ab, propagating loop depth to a field 5a91c83ce8, element type for OIND of slice 3042463d61, self-assignment handling ff468a43be/859cf7fc0f/499fbb1a8a/4cf33e361a, unnamed parameters be09bdf589, anonymous receivers as non-escaping 88466e93a4).

In 1.13 Matthew Dempsky added a complete reimplementation, escape.go, behind -newescape (97c4ad4327): “focuses on simplicity”, builds a data-flow graph of EscLocations with edges carrying a dereference count, and then walks from each location to find whether its address reaches a location that outlives it (the heap location sets escapes). It was enabled by default in the same release (996a687ebb, marked RELNOTE because stricter checking may break code violating the unsafe.Pointer rules) and the flag removed in 1.14 (991b0fd46c). Fixes along the way: CONVIFACE of a non-direct interface must flow its data to the heap (0349f29a55), parameter tagging refactored and then integrated before escape analysis completes (23bf6af996, b9704872d1), and diagnostics restored (063d0f11e5, 4cde749f63, 606019cb4b).

1.14 made it faster and richer: a proper work queue replaced fixed-point re-walks with the “walk from the heap last, ensure escaping objects have an edge to heap” invariants relaxed (867ea9c17f), and graph construction was optimized by marking heapLoc.escapes, skipping edges for oversized allocations and for objects whose address flows somewhere that naturally outlives them (262046716c). The leak encoding was replaced by an EscLeaks abstraction (05a805a6de, a0894ea5b5): the old scheme could record at most one dereference and only the first 4 parameters / 6 derefs; the new one is a [8]uint8 array per parameter. 1.15 added precise handling of method values (receiver flows to the closure and method receiver, not directly to the heap, 2a2423bd05) and a stricter notion of unsafe rule #4 (f049d911e9). 1.16 added staticValue to resolve calls through never-reassigned local variables and closures (c0417df156), reasons from mustHeapAlloc (095e0f48a1), and escape of OCLOSURE/OCALLPART (82c45eb681). In 1.17 (dev.regabi) the package was split out (de454eef5f), the escape state was split (67ad695416), function literals are walked in place so closure conversion can be done during escape analysis (b1747756e3), capture-by-value is recomputed there (fd43831f44), PAUTOHEAP marking was moved out of escape into SSA construction (f97983249a), and a bug about heap-allocated results flowing to parameter summaries was fixed (a429926159).

Design. The inliner works on the typechecked AST (inl.go): caninl computes a “hairiness” cost with a budget (80 nodes) via hairyVisitor; mkinlcall copies the callee body and replaces parameters with inlvars, wrapping the result in an OINLCALL. Inlined call sites are recorded in an inline tree for positions and DWARF. In this era the work was about widening the set of inlinable shapes, and tuning costs.

1.10 gave inlining closures with captures (c4b65fa4cc, mapping captured vars to temporaries like parameters), non-code nodes ignored (812b34efae), go:yeswritebarrierrec functions excluded (4e64ee423c), functions that call recover excluded (b5b35be2b8, because recover matches its caller’s argument frame pointer). 1.11 was the mid-stack year: variadic functions enabled (09d4455f45), inlining parameters refactored into explicit costs with panic inlinable and -l=4 expressed as a cost (87a18c6109), a stricter threshold of 20 instead of 80 for functions over 5000 nodes (5fc70b6fac, motivated by reflect.Value’s cost being exactly 80), constant if statements treated as free after front-end deadcode learned &&/|| (2dbf15e88e), struct == cost considers component count (b638760dad), and go:norace not inlined under -race (c6e455bb11). 1.12 encouraged “single-call bodies” by making calls cheaper (13baf4b2cd), lowered call cost from 60 to 57 (624e197c71), and removed old budget hacks that stack tracing made unnecessary (555d8c455a); the generated (*T).M wrappers also became inlinable (fa913a36a2) and mid-stack inlining tracebacks were redone (69c2c56453). 1.14 inlined reflect.Value.UnsafeAddr/Pointer only when checkptr is off (e9850462aa). 1.15 allowed mid-stack inlining within a recursion cycle, tracking already inlined functions at a call site (ed7a8332c4), made intrinsic inlining cost one (956f64888d), and logged inline failures rather than successes (fced302aa1). 1.16 allowed unlabeled for loops (497ea0610e), staticValue in inlining logic (1bcf6beec5), single-return functions with unnamed results (f2c0c2b902), functions evaluated in go/defer argument lists (4fb4291388), and set Name.Defn for inlined parameters (cced777026). 1.17 rewrote helpers on the new IR (ir.EditChildren, ir.DoChildren, ir.DeepCopy replacing inlcopy), simplified closure inlining (fad9a8b528), lowered OCONVOP cost (adb467ffd2), and gated function-with-closure inlining behind -d=inlfuncswithclosures defaulting to off (8027343b63) until a bug was fixed.

Design. Profile-guided optimization (PGO): hot-call inlining, devirtualization, profile preprocessing

Span: Go 1.20 → Go 1.28 · Status at HEAD: on whenever a profile is supplied; drives inlining and both kinds of devirtualization; 1.28 also accepts Linux perf profiles

  • background Chen, et al. AutoFDO: Automatic Feedback-Directed Optimization for Warehouse-Scale Applications. 2016. listed in Go: A Documentary

Design. The compiler reads a pprof CPU profile and turns it into a weighted call graph. Since 1.23 the IR-independent part lives in cmd/internal/pgo, which cmd/compile and the cmd/preprofile tool share. Each edge is a NamedCallEdge: caller, callee, and the call site’s line offset from the caller’s Function.start_line. Only the last two frames of each sample count as an edge. The serialized form is sorted by weight. cmd/compile/internal/pgoir (named pgo until 1.23) binds those names to ir.Funcs in an IRGraph. Callees outside the current package are looked up in export data. A call site is “hot” if its edge is in the top pgoinlinecdfthreshold percent (default 99) of cumulative edge weight. Hot call sites get an inlining budget of pgoinlinebudget (default 2000) instead of 80.

PGO devirtualization (devirtualize/pgo.go) works on interface method calls and, since 1.22, on calls through function values. It picks the hottest concrete callee recorded for the call site and rewrites i.Foo() into if c, ok := i.(Concrete); ok { c.Foo() } else { i.Foo() }. Inlining can then inline the direct branch. From 1.22 devirtualization and inlining run interleaved, so a devirtualized call can be inlined in the same pass. The debugging knobs are -d=pgodebug, -d=pgoinline, -d=pgodevirtualize and pgohash; pgohash bisects individual PGO decisions.

Inliner: budget, closures, and the interleaved inline/devirtualize driver

Span: Go 1.18 → Go 1.28 · Status at HEAD: classic budget-80 inliner with closure, parameter-call and hot-path discounts; runs interleaved with devirtualization (inline/interleaved); functions calling recover became inlinable in 1.28

Earlier history: Inlining (inl.c → inl.go) (Go 1.0 → Go 1.9) · Inlining: budget, mid-stack inlining, closures, and what became inlinable (Go 1.10 → Go 1.17)

Design docs & discussion
  • design doc Go 1.22 inlining overhaul listed in Go: A Documentary

Design. The inliner in cmd/compile/internal/inline gives each function a cost with hairyVisitor and compares it to inlineMaxBudget (80). It then walks call sites and replaces each inlinable call with an OINLCALL body. Since 1.18 walk flattens that body (c45d0eaadb). Since 1.20 unified IR does the body copying (noder reader inlCall), and transitive inlining happens only after the AST has been edited.

The cost model has gained discounts over time:

  • encoding/binary loads, stores and appends are cheap (17c513e722, 629c0b3a6e).
  • Taking the address of a field at offset zero costs 0 (638c9aad5f).
  • A call to a function-typed parameter costs 17 instead of 57 (a464ffda3e). Calls to closure variables are discounted (ad7f736d8f).
  • A function that contains a closure gets double the budget (170436c045), and a closure called only once gets a very high budget (d524c954b1).
  • abi.NoEscape is cheap (b6efbd4efc).

Big functions (isBigFunc) cap callees at 20. Recursion is detected by walking the inline position stack, not by a separate check (cad4dca518).

Since 1.23 cost analysis (CanInlineFuncs) is separate from applying inlining. Since 1.24 the “interleaved” driver in inline/interleaved alternates devirtualization and inlining until a fixpoint, and honors b.Loop and go/defer restrictions.

Escape analysis: call modelling, closures, func-variable callees, and solver speed

Span: Go 1.18 → Go 1.28 · Status at HEAD: cmd/compile/internal/escape resolves calls through closures and func variables, has a heavily optimized solver, and owns go/defer wrapping; the zerocopy string→[]byte conversion is controlled by a debug flag

Earlier history: Escape analysis (esc.c → esc.go) (Go 1.0 → Go 1.9) · Escape analysis: the esc.go fixes, the escape.go rewrite, and the move to package escape (Go 1.10 → Go 1.17)

Design. Escape analysis builds a data-flow graph of locations connected by holes with dereference counts, then solves it. In the solve phase, walkAll/walkOne repeatedly walk the graph from each root and propagate the escapes, persists, mutates and calls attributes.

In 1.18 (dev.typeparams), call handling moved from order.go into escape (call.go). Escape now rewrites go/defer calls into argument-free wrapper closures, handles method-expression calls, and wraps constant arguments without allocating. In 1.22 the go/defer normalization moved to typecheck, and ir.CallExpr.GoDefer marks such calls.

In 1.22 the location attributes became a locAttr bitset. Indirect closure calls (func(){...}() stored in a variable) are tracked statically, and so are flows into *p = ... and mutating builtins. The mutates attribute lets []byte(s) reuse the string’s bytes when the result is never mutated (the zerocopy optimization).

From 1.25, the ReassignOracle lets escape find the static callee or static value of variables assigned once. In 1.27 this was generalized to FuncAssignments: when a func variable has several known callees, their parameter escape behaviours are merged through a teeHole.

Solver speed became a theme from 1.25 on, driven by typescript-go/internal/checker, a package where escape analysis dominated compile time:

  • walkOne stopped touching ir.Nodes in its inner loop. Build time fell from 91.8s with go1.24.0 to 65s (04a9b16f3d).
  • Work is reordered to visit locations likely to reach the heap first. Build time fell from 91.8s to 17.6s, about 5× (74304cda29).
  • Packages with many closures got faster (f506ad2644).
  • In 1.28, walkOne reuses one queue: −28.8% bytes allocated (ab4ad11bad). Roots with equivalent state are coalesced into one multi-source walk: TypeScriptGoChecker −48.5% in compilebench (372c766cdd). For this, the predecessor paths used for diagnostics became immutable snapshots (e78076d579).

Span: Go 1.21 → Go 1.28 · Status at HEAD: variable-size make and append use a 32-byte stack buffer when the slice does not escape; a move2heap slice pass handles slices that escape only at the end of their lifetime; runtimefreegc is off by default; bug fixing ongoing in 1.28

  • tracking issue #71359 cmd/compile: avoid allocs by better tracking of literals for interface conversions and make referenced by 8 of this thread's commits
  • motivating issue #8618 runtime: don't allocate for non-escaping conversions to interface{} referenced by 2 of this thread's commits
  • discussion a safe free of memory proposal, runtime.FreeMemory() golang-nuts · linked from #74299

Design. Three mechanisms keep allocations off the heap.

First, constant and zero-value interface conversions. Escape analysis propagates constants found by ReassignOracle, so a conversion any(x) with a known x reads a static read-only global instead of allocating. Zero values use the global zeroVal. A composite literal converted to an interface becomes a read-only global when all its fields are constants. Debug hash literalallochash.

Second, variable-sized make. When the result does not escape, walk emits if cap <= K { var arr [K]E; s = arr[:len:cap] } else { s = makeslice(...) }. K is 32 bytes, tunable by a debug flag, and the decision can be bisected with variablemakehash. append to a non-escaping nil slice gets a stack backing store in the same way. Lengths and capacities that are provably constant are rewritten to literals first, so the plain constant-size path applies.

Third, the slice pass (cmd/compile/internal/slice, 1.26). It tracks whether a slice variable exclusively owns its backing store. It inserts move2heap at the point where ownership ends, such as a return, so a slice built with append in a loop lives on the stack until it escapes. A related alias analysis can call runtime.growsliceNoAlias, which frees the old backing store right after growth; this is gated by GOEXPERIMENT=runtimefreegc. The prove pass learned that both arms of the resulting Phi(SliceMake, SliceMake) share the same len and cap.

Prove pass and bounds-check elimination: from poset relations to a dense limit table, topo-sorted walk, and division-aware proofs

Span: Go 1.19 → Go 1.28 · Status at HEAD: prove (ssa/prove.go, moved to ssacompile/prove in 1.28) keeps a per-value signed/unsigned limit table plus a relation poset; it walks blocks in topological order; divisibility and divmod rewriting run after it

Design docs & discussion

Design. Prove walks the dominator tree. Branch conditions and value definitions add facts to a factsTable, which then removes bounds checks, nil checks, and impossible branches. It also rewrites operations whose result it can determine.

Keith Randall’s 1.24 rewrite (553443d41f) rests on one observation. Relations between pairs of SSA values may need O(n²) space, but relations between a value and constants need only O(n). So every value gets a dense limit entry, a slice indexed by value ID that holds signed min/max and unsigned umin/umax. The poset keeps only the value-to-value orderings. Once the constant logic moved into the limit table (3b96eebcbd), the poset’s constant handling was ripped out (b97971ea2e). flowLimit then computes limits from operands for each op. Jorropo added rules over two cycles: bit-length, trailing zeros, XOR, OR, Mod/Div, truncation, complement, negation, min/max, popcount, and shifts.

Later structural changes:

  • 1.26 walks the blocks in a topological order, so facts are learned in a single correct pass (53be78630a, #68857). This removed several flowLimit workarounds.
  • 1.26 moved the division optimizations out of the generic rules into new divisible and divmod passes that run after prove, followed by a “middle opt” generic pass (9bbda7c99d). Prove now sees the original x/c and x%c operations, and the rewrites still happen before decompose.
  • Loop BCE (loopbce.go) finds induction variables. Since 1.22 it inverts loops to count down to zero where possible (bac4e2f241).
  • 1.27 fixed an overflow check that could remove a needed bounds check (f5b77a7e2f, CVE-2026-27143).
  • 1.28 fixed “time traveling” proofs: facts about a value’s arguments were applied to the whole block, before that value had executed (a595f29385).

Design. SSA memory is a chain of Store/Move/Zero values threaded through a memory argument. Several passes shrink that chain.

  • mem2reg (1.28). A port of LLVM’s PromoteMemoryToRegister. It promotes address-taken stack scalars whose address is used only by loads and stores into SSA values.

Switch lowering: jump tables, type-switch caches, and switch lookup tables

Span: Go 1.19 → Go 1.28 · Status at HEAD: integer and string-length switches use jump tables (off under -N and retpolines); large type switches jump on type-hash bits behind per-site runtime caches; constant-returning switches become lookup tables (1.27)

Earlier history: Switch, type-switch and select lowering (Go 1.0 → Go 1.8) · Switch lowering, select, and type switches in walk (Go 1.10 → Go 1.15)

Design docs & discussion
  • motivating issue #5496 cmd/compile: compile dense, pure-integer "switch" into jump table referenced by 2 of this thread's commits
  • motivating issue #34381 cmd/compile: use hashing for switch statements referenced by 2 of this thread's commits
  • discussion Jump Tables in 6a golang-nuts · linked from #5496

Design. In 1.19 Keith Randall added BlockJumpTable. The 1ba96d8c09 message frames the tradeoff: a jump table is a single indirect branch, which can choke the branch target predictor, while a binary search spreads predictor state across many branches and can win when case selection is repetitive. Jump tables are therefore used only above a minimum density and case count.

String switches dispatch on the length first, so the outer switch can use a jump table (3d8cb26504, −9% on both predictable and unpredictable benchmarks). Interface→concrete type switches with many cases use a jump table on bits of the type hash (4711299661, −10.9% predictable, −17.6% unpredictable).

The bigger 1.22 change was per-site runtime caches. A type switch on an interface (39263f34a3), a type assertion to an interface (cbcf8efa5f) and convI2I (afd7c15c7f) all consult a small hash table of sampled concrete types before calling into the runtime. The table records the matched case and the resulting itab, so a repeatedly seen type avoids the runtime call. These caches use the new internal/abi runtime type mechanism (9ab5121691).

In 1.27 qmuntal’s lookup-table lowering turned switches whose cases are integer constants and whose bodies just return constants into an indexed load from a static table (2a902c8a8a). It was then extended to all constant return types, fallthroughs, and (in 1.28) assignments.
