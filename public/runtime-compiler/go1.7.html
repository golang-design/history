Go 1.7

Part II · commits first contained in tag go1.7 ^go1.6 (tagged 2016-08-15) · 1594 in-scope commits

SSA backend for amd64: CSE, nil-check elimination, prove/BCE, a global register allocator. Mark-bit-based allocation (allocBits/freeindex). Smaller type descriptors (nameOff/typeOff). Binary export data by default. Linker speed and memory campaign. Frame pointers on by default on amd64.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Memory management: GC and allocator (Go 1.0–1.17)

dev.garbage bitmap allocator (allocBits, freeindex, ctz), allocate-black, O(dirty) stack rescan, concurrent stack shrink, 32-bit full address space.

  • Decentralized GC state machine and mark termination simplification — Done: only per-P gcWork (0168c2676f), markrootDone generalised (c14d25c648); reset mark state before STW (9ab9053344). Left open: nothing noted.
  • GC pacer: trigger controller, assists and background utilisation — Done: allocate black plus counting black allocations toward scan work (6002e01e34, 479501c14c, 64a26b79ac); floating garbage estimate removed (c8bd293e56); reduced assist extra credit (ccca9c9cc0); sweep ratio in gcpacertrace (17f6e5396b). Left open: next_gc still the trigger not the goal.
  • Stack scanning: conservative, precise by frames, stack barriers, hybrid barrier, async safe points — Done: O(dirty stacks) rescan, no global rescan, concurrent shrink (2a889b9d93, b49b71ae19, f11e4eb5cc, e8337491aa, 269c969c81, 9f263c14ed, efb0c55407 span root marking out of mark termination). Left open: rescan still needed.
  • Precise heap scanning: type information, the heap bitmap and GC programs — Done: conditional branch removed from heapBits.bits (4eb33f6b8d), clears reduced (0d26efb12a), first-word scan bit reclaimed (a20fd1f6ba), morePointers/isPointer without branches (a5d3f7ece9, d5e3d08b3a). Left open: noscan still checked through the bitmap.
  • Allocating from mark bits: allocBits, freeindex and ctz — Done: the allocBits/freeindex/allocCache scheme (2ac8bdc52a, e1c4e9a754, dc65a82eff, 3479b065d4, 4093481523, 1354b32cd7, 2063d5d903, 2fb75ea6c6); stackfreelist added (aed861038f); mspan.start eliminated for base() (b7adc41fba, 3e2462387f); allocation-count fixes (d97625ae9e); publication barrier even for noscan objects (d8b08c3aa4).   • Size classes, tiny allocator and mcache/mcentral — Done: user-visible runtime.KeepAlive (6ab45c09f6), maxSliceCap for division-free slice caps (a4dd6ea152, MakeSlice -32%). Left open: nothing noted.
  • Scavenger: returning memory to the OS — Done: physical-page aligned scavenging (2cdcb6f829, 1151473077, f407ca9288). Left open: nothing noted.
  • Heap address space: contiguous arena to sparse arenas — Done: full 4 GB on 32-bit (e6ec82067a). Left open: nothing noted.
  • Mark work distribution: parfor, work buffers, gcWork and root jobs — Done: only per-P gcWork (0168c2676f, 7b229001e7), gcWork tryGet/put fast paths (1354b32cd7), scanstack takes the gcWork (3be48b4dc8). Left open: nothing noted.
