Lexer, grammar and statement syntax (semicolons, chan operators, conversions)

Span: Go 1.0 → Go 1.0 · Status at go1.17: the surface syntax is the Go 1 one; the yacc grammar go.y and hand-written lexer lex.c stayed the parser until the compiler was rewritten in Go (not in this range). → continues as The syntax package (parser, scanner, tree) (1.18+)

Continues in: Parser: from yacc to a hand-written recursive-descent parser (Go 1.1 → Go 1.8)

Design. The frontend is src/cmd/gc in C: a bison/yacc grammar go.y that builds Node trees directly, a lexer lex.c, and per-architecture code generators (6g/8g/5g) that initially owned most of the semantic code. In 2008 almost every syntactic rule of the language was still moving, and the compiler followed the spec as it was rewritten week by week. Statement termination is the clearest example. The first optional-semicolon support (8200a0b088, 0006c83231, c242b53d22) was replaced by “all statements and declarations are terminated by semicolons; they may be omitted at top level and before/after a closing ) or }” (d364d28142), which doubled parts of the grammar; in June 2009 the rule was moved into the lexer, which now inserts the semicolon itself so the type and statement grammars no longer needed duplicated variants (8abcdee175, 179 insertions, 284 deletions). Follow-ups made 6g match the spec exactly: no semicolon after the package clause, one allowed after imports (aaaa1fc69b), a semicolon inserted at EOF (ec13ed1fce), and mandatory { } around else blocks (58e19aa4cb, 2011). The if condition became mandatory (52943bfe4d, 2011).

Expression and type syntax went through several iterations. Conversions and constructors were first T{} and T(expr) (0194aaf918, Ken Thompson, which also stopped treating func as a type), then composite literals briefly became T(...) with a warning for the brace form (07244f7c80, Feb 2009), and returned to T{x} with a stricter split between T(x) conversion and x.(T) assertion a month later (49cc649e59). Parentheses were allowed to disambiguate types (ebc10db3e1). Channels first had a <-/-< pair, then a new syntax (ac048ce7f4) and in September 2008 binary <- is send and unary <- is receive, with case a := <-ch: and case a = <-ch: in select (47919799b4, 304440356d). Directional channel types were enforced in May 2009 (f4d3d22a94) and chan <- chan precedence and func() func() were fixed in 2010 (7abb4b3a96), plus send precedence (0e47460915). In December 2008 *chan became chan and *map became map, with new(T) taking the pointee type: “mainly a syntactic change: the compiler representations don’t change (chan and map are now hidden pointers like string)” (dc7b2e98d2, 88b5c5f0f8, 316d377ac2). The range statement arrived in December 2008 (26b357ca5b, b79272d9a2, ae5a475e20), &^ and &^= in March 2009 (bb02e481d2), [...] closed arrays in January 2009 (b0f627a6e1), and empty var ( ) factoring in October 2008 (5f1202428b). Redundant iota rules were redone twice (d915b96100, c597845e13).

The lexer also gained several user-visible rules: control characters other than white space are rejected (2538cf747b), · is disallowed in source (9e497c3656), backslash-newline in strings is illegal (0c222d6e49), //line file:number directives were added in July 2010 (444066e56d, 19d7fc4026, with the earlier //line number file form changed), and colons were permitted in the directive file name (ecda0fa5d4).

Package system, visibility and import resolution

Span: Go 1.0 → Go 1.0 · Status at go1.17: capitalisation-based export and -p/-D/-I import resolution as of go1; compiler flags later reworked by the build system. → continues as Package paths, -p, and build-system contract (1.18+)

Design. Visibility changed repeatedly in 2008–2009. First came export adjectives on external var, const, type and func declarations (989676d2ba, 695f83a9e0, b59b551be7), and in November 2008 a package keyword for package-local declarations (d3f6093931, 9c7b064043). In January 2009 the export name-list statement was removed and “package local” became the default; the compiler warned when the name’s case did not match the keyword (07d344e442, 3decb42e6f, 605d0746c5). Case then became the real rule: other packages’ lower-case names are rejected in struct field selectors, method calls and P.t (06869eedf9, aec4d3194a, 61590c4c44), assignments to private fields during initialization (9da6666a8a), implicit assignment to non-exported fields in copy and append (151b2f1509) and then the opposite relaxation for method receivers and copy of structs with unexported fields (0b209b36b6, d03611f628).

Package lookup went from a flat global namespace to explicit paths. 6g autoloaded imports via #pragma lib (e90ae879d6, 12c81a0ce8, f95da9a639), later by searching a pkg directory, .6 before .a, archives with __.PKGDEF and 0-length __.SYMDEF (63a84348cc). -I DIR added include directories (062d6998ab), local-path lookup was separated from standard directories (70e232e668), the package global name space was eliminated (531e6b77c8, Jan 2010) and the runtime type data records full package paths (1cecac8134). The name main stopped being reserved (c1a695c160, daffc2d2ef). Unused imports are an error (73e52ae971) and print the path (f1550482fa). Import cycles: -p tells the compiler “if you see an import of this package, give up early”, because a cycle otherwise shows up as two different copies of the same package and type-signature mismatches (1e480cd1ad). Import-path hygiene landed in early 2012: \ diagnosed (33f3afa7af), special characters rejected (dc38756ce1), absolute paths disallowed (d0d251f858), ~ allowed on Windows and slash handling (d0a4c9bb62, 29199aa4e4). Relative imports were reworked for cmd/go with a -D prefix option: import "./foo" with -D a/b/c becomes a/b/c/foo, so a _/home/gopher/foo pseudo-hierarchy makes relative imports ordinary paths (604f375110).

Export/import data format

Span: Go 1.0 → Go 1.0 · Status at go1.17: textual export data in the object file’s __.PKGDEF section was still the format at go1 and in 1.17 had moved through the binary format and then indexed export data → continues as Unified IR: one serialization for noding, stenciling, inlining and export (1.18+)

Design. The compiler writes a text description of everything a package exports into the object file, delimited by $$ markers, and the importing compiler parses it with a second yacc entry in go.y (the “import grammar”). The first version dated June 2008 (2254a8ee99, 343f5aa7b4, 4528854308 made names unique). On 2008-10-03 Russ Cox rewrote it (b8babed7c2, 1827-line delta, export.c shrank by roughly 700 lines): declarations are printed as Go-like type flag.Value interface {...} with fully qualified identifiers, the delimiter changed from (( )) to $$, and sys.go uses a leading export. Other early decisions: only explicitly exported types are exposed to the importer (fb2c66710c), type names “live at the name” so type T struct{ next *T } and type T *struct{ next T } work without forward declarations (74e2e087e2), \n$$ as the section delimiter (4958d41d3b), tag strings on struct fields and across multiple names (f27aaf4819, 1850b29da6, f2b1536328), ... (2fef4c7198), embedded types (21617250f4), and a separate section for non-exported types referenced by exported ones (aacfbb461b). Constants are exact: negative constants (c3d841f5d4), large constants (2b75556436) and multi-precision floats via a decimal-integer “p” exponent syntax (f8797daa9f); complex constants (713e3e1541).

From 2011 the format was prepared for inlining: all transitive dependencies are listed, with indirect imports marked, “purely informational” (e6f3aa6c36); string literals used as package qualifiers are prefixed with @ which removed the : before tags (b536adbfba, Luuk van Dijk); further changes, with a “minimal change to gcimporter” (40b2fe004f); tags allowed on parameters (56668283f1); nil literals exported without inferred type (feaa9ed10a), implicit type bug fixes (5c52404aca, 419c53af30, 77aaa3555d), field names in struct literals inside exported inline bodies not qualified for embedded builtin types (6ff01f01f4), and a limit on the size of exported recursive interfaces to stop memory blowup (aa63a928ea). The byte/uint8 distinction was preserved in errors and import data (862179b0f5).

Design. Until Go 1.4 the frontend was C in src/cmd/gc (lexer lex.c, yacc grammar go.y, typecheck.c, walk.c, esc.c, inl.c, sinit.c, …) shared by the per-arch code generators 5g/6g/8g. The Go 1.5 cycle converted it mechanically to Go. The runtime-C-removal branch work started it: fd2bc95d53 ([dev.cc]) changed cmd/gc to emit an -asmhdr header (struct field offsets and consts that cmd/dist used to scrape from the C compiler), to accept //go:cgo_xxx and //go:linkname directives, and to hard-code that interfaces contain only pointers. The translated code was committed as cmd/internal/gc (9c8c0e729d “reconvert to pick up bug fixes”, f6791da7ad for new6g etc.), still driven by a Go-ported yacc (cmd/yacc, go.y → generated y.go). Matthew Dempsky’s cmd/yacc work restored the “unexpected X, expecting Y” syntax-error style that Bison produced (e7d9f81645, 398bf9d5a0, 4f2a73011f, 82e1651a24), and a1bb3030c8 made yacc emit arrays instead of slices.

C idioms were then peeled off: Strlit/Zconv deleted (bed1f90d08), C hash tables replaced by Go maps (d0b59deb71), md5.go replaced by crypto/md5 (392434e1d0), Mpint/Mpflt re-based on a vendored math/big (e5a0d6399e, 4da157a723, 888767fcc4, 5bb89eb009; the vendored copy was refreshed repeatedly: 1e48683708, 65cd1ba682, f39cca94af, 646939c0e3, 5693bee0f1), Val.U became interface{} (13485be939, Node 424→392 bytes) and many int flags became bools (4a174ee4be, 5bf428ef80, 7885de55dc, d328756a69, 75883bae28, e7fe9f56ea). The package was then moved to cmd/compile/internal/gc with the binary renamed from 6g to compile (b3a508c03e usage names).

The second half of the effort was memory: Node dominated compiler memory, so func-only, name-only and param-only fields were split out into Node.Func, Node.Name, Node.Param (57279ba752 504→416 bytes, 76ec0ee53a, f4ab8203ba, 3ed9e4ca3c, bd8bb67357), and a long series moved fields into those substructures and deleted dead ones (ffef180f82, 66be1481df, 496ad0a286, 4fdd53680c, 71080fbb9e, 60e5f5bdff, 140ef3c59a, ac2bda1b00, 3007e953d0, 11322d45a1, 3c3019aa51, fd2154f906, bd4fff6358, da094f19f1, f1f0eda446, 3be7f28e82, 81d5810be9). cd9f417dbb documented which Node fields each Op uses.

Design. Export data in Go 1.1–1.5 was text: a $$ section of Go-like declarations written by export.c, parsed by the ordinary lexer/parser. Inlinable bodies were exported as source-like fragments, which made inlining bugs show up as export-data bugs: 8d95245d0d, 761830f481, fc7b75f216, 78f5b616fc, 62891fb811, 20ebee2c31 and c1fc8d5296 all repair missing or corrupted body exports; constants were exported in hexadecimal (fbaf59bf1e) and later without the original expression (f09887cdce).

Go 1.6 added ae2f54a771, Robert Griesemer’s compact binary export format (bexport.go/bimport.go) under -newexport, importable in “mixed mode” with the textual format; export sizes were about 26–30% of the textual size for std packages in the commit’s table. It initially lacked inlined function bodies. Binary-escaping (e6ccfc1ad1: no $ bytes inside) and -importmap before unsafe handling (a8fc547f78) followed. In 1.7 4598382724 exported and imported all bodies without hooking them up, a9ea36afbb completed body export (three sections: platform-independent objects, objects pulled in by inlined bodies, and the bodies themselves; “completely compiler-specific and easily changeable”), compiler-specific flags moved to a compiler-specific section (b1851a3c11, 7d0d122247), position info was added (5c593a3227 “first cut”, delta-encoded line numbers and canonicalised strings, 14% size increase; e8d4ffb766 fixed the node used; 6c11e2710e delta-encoded filenames, 15–25% savings on some packages; 889c0a66fc disabled position export “for now”), and 7538b1db8e switched to binary by default on 2016-04-15, quoting ~65% smaller export data, at least 62% faster writes and 37% faster reads, with -newexport=0 as the escape hatch. feb6131b1a added -linkobj to write the object in two parts (export data for compiles, everything else for linking) and moved two bits the linker needed into the object header proper.

Go 1.8 removed the textual format (b4e9f70412, f50ced6d73, 074d6a649c), then reintroduced version-0 binary reading (c85b77c22b) and added a version byte with graceful failure on skew (5a6f973565), and exported aliases (03d81b5ed9, later revert of user visibility 8e970536df). 1.9 added linknames to export data (e3efdffacd: lets -l=4 inline functions that contain linknamed calls), position info in inlined bodies (9fd359a29a: +8–20% export size, accurate line numbers for cross-package inlining), type-alias format (49de5f0351: embedded-field name modes), interface embedding information (ee272bbf36), a cheaper position encoding with a -64 new-file marker and /-component paths, bumping the version to 5 (a6b16e0024: about 8% smaller), ad8c17b703 not exporting dead code in inlinable functions, and ff0748670c/2123a6c644 fixes for exported bodies and line-directive-relative positions.

Design. Escape analysis (esc.c, later esc.go) assigns each Node a “loop depth” and tracks whether addresses flow to the heap, to a longer-lived scope, or to results, producing per-function parameter tags used at call sites. Go 1.1 added tracking of the flow from input to output parameters (976ca1a47d step 0 synthesizes names for anonymous results, 75692424d2/507fcf37d2 the analysis, 572d984eaa, 71282131a1 fixes), applied results to closures (9fe60801ae: avoids allocating closures used as “macros”, defer args or Walk idioms; BenchmarkCallClosure1 119→7 ns), handled method values (38e9b0773d) and added a noescape marker for extern funcs (fd178d6a7e). Go 1.2 moved big stack variables to the heap (1f4d58ad5d) and fixed wrapper escape analysis (7cfa8310c7). Go 1.4 made it run always, even in -N mode (00d2f916ad) and fe3c913443 fixed an unsoundness with functions returning an indirection of a parameter, which mattered once stacks were copied (heap objects pointing at stack variables would not be updated). The fix tags such parameters as “content escapes” without recording which result; a more precise mapping was explicitly left out as a trade-off (more precise means fewer heap allocations).

Go 1.5 improved flow precision (7fbb1b36c3, David Chase): the per-function summary records outK = paramJ, outK = *paramJ, heap = paramJ, heap = *paramJ in a tunable number of bits (2 chosen), “level” split into three parts to model address-of cancelling indirection; 420 fewer heap allocation sites compiling std and a 15% reduction in allocations performed by the compiler on html/template. Dmitry Vyukov’s series then used escape results to stack-allocate more: 32-byte buffers for non-escaping []byte→string and concatenation (e6fac08146), []byte(str) conversions (9568126f35), string(rune) (4ce4d8b2c4), non-escaping make(map) with hmap and one bucket on the stack (b3be360f16, 75 std cases, NewEmptyMap 124→55.7 ns), interface backing storage (2270133981), &T{} like new(T) (2af3cbe308, 1.1), and no copy for range []byte(str) (71be013842). Go 1.5 also ran escape analysis after method-wrapper generation (5be61b18d4); Go 1.7 eliminated PPARAMREF (20803b845f), changed liveness handling of heap-escaped params with the new PAUTOHEAP pseudo-class (b6dc3e6f66), and stopped leaking dottype expressions (5c5e8d4105). Go 1.9 stopped updating outer variables after capturevars completes (61336b78c1) to make results deterministic under concurrent compilation.

Closures, method values and variable capture

Span: Go 1.1 → Go 1.7 · Status at go1.17: still the design (capture by value when never reassigned and not address-taken; closure call → function call) → continues as Old typechecker and IR node-model cleanup (1.18+)

Earlier history: Closures (Go 1.0 → Go 1.0)

Design. Closures are OCLOSURE nodes whose body becomes a hidden top-level function (25922c0658 introduced hidden closure functions earlier in Go 1.1). Method values x.M (d3c758d7d2, 1.1) are compiled as closures over the receiver (176 lines in closure.c). Go 1.5’s Dmitry Vyukov work changed the capture model in two steps. 0e80b2e082 “capture variables by value”: the spec says capture by reference, but if a captured variable is neither address-taken nor ever assigned after capture it is effectively const, so the closure copies it; about 80% of std captures became value captures, with zero heap promotion of PPARAM to PPARAMREF (BenchmarkCompressedZipGarbage allocs 153→126). Range variables and outputs needed special-casing (eaa872009d, 3bf005cea3). c4ee44b7b9 transforms direct closure calls (func(){...}(), go func(){}(), defer func(){}()) into plain calls with closed variables passed as arguments, so no heap context is needed (CreateGoroutinesCapture 6→2 allocs); it split the work into capturevars (decides capture mode, needed before escape analysis) and a new transformclosure pass run just before order/walk, and the call-site rewrite happens in walk of OCALLFUNC(OCLOSURE). Closure names became simpler (3a0fbfab57), called closures get captured args prepended to their params (731dcdae6d), and Go 1.6 made captureless closures constants (4f97ec0866): they can initialise globals at link time, which removed fmt.ssFree’s reachability from fmt.init and shrank hello-world by about 4%. In Go 1.7, PPARAMREF and Func.Outer were deleted (20803b845f, 93369001c7), Func.Cvars became a Nodes (52d9479e3b, 922ce58de0) and transformclosure was simplified (c7917de0bb); b64f549ba9 added -d closure and detection of leaking closures in the runtime.

Span: Go 1.2 → Go 1.7 · Status at go1.17: write-barrier insertion moved into SSA later; frontend marks (pragmas, OASWB) removed in 1.9 → continues as Old typechecker and IR node-model cleanup (1.18+)

Design. For the concurrent GC, the compiler had to supply precise pointer maps and, later, write barriers. The compiler-side steps were: precise stack-frame liveness (precisestack, disabled for 1.2 in 30ecb4cd05: “the zeroing required without it is too expensive”, re-enable by GOEXPERIMENT=precisestack; enabled by default in 1.3 by ecf700b5ee, reverted/relanded as 53061193f1 after a 32-bit fix, costing about 5% of all.bash time and tracked as issue 7345); this guarantees interface values are always initialised so the type word is trustworthy. Cost reduction followed in 1.3: shorter temporary lifetimes through orderexpr-allocated temporaries with VARKILL (daca06f2e3, 96d90d0981: ambiguously live temps in godoc 860 → 711 → 121 → 23), and compact liveness bitmaps (4676fae525: one bitmap length per set, duplicate bitmaps merged, bitmap sets named gclocals.<md5> and dupok so the linker dedups; bitmap bytes in godoc 1326600 → 245580, binary −9%). Liveness got 10x faster in 1.4 (7aa3031eba). Go 1.4 emitted write barriers (fcb4cabba4: *p = x becomes runtime.writebarrierptr(p,x); “the goal is to slow things down (and be correct)”, BinaryTree17 +10.7%), with 2/3/4-word specialisations (a3416cf5cd), elision for *x = T{}-style zeroing (3c40ee0fe0) and for x = x[0:y]/x = append(x, ...) Indexed export format and the export-data lifecycle

Span: Go 1.10 → Go 1.17 · Status at go1.17: the indexed (iexport) format is the only compiler export format, now carrying positions with columns, type information on inlined bodies, closures and ABIs → continues as Unified IR: one serialization for noding, stenciling, inlining and export (1.18+)

Earlier history: Binary export data and the object-file split (Go 1.1 → Go 1.9)

Design. Up to 1.10 the compiler wrote a sequential “binary export” (bexport.go): importing a package processed every declaration and every inline body in order, even if the importer used none of it. In large Go programs the export data was big because of transitive type declarations and inline bodies. The indexed format (ca2f85fd3f) writes an index of declaration and inline-body offsets so iimport lazily loads only what compilation touches; the commit’s benchmarks compare -iexport=false and -iexport=true across -c and -l settings. It is read lazily through Sym.Def placeholders created by the importer; dd71e3fef4 and ae2a2d12f6 consolidated how imported declarations and init functions are wired up so both importers share code.

Before iexport there was incremental work to make export cheaper: skip duplicate inline method bodies already imported (f0b3626904, which for a protobuf-heavy package cut compiler RSS from ~12GB), don’t export unreachable inline method bodies (8684534321), record InlCost in export data so the importer does not recompute (a509cae90d), and simplify exporting of the universal error type, OTYPE and ONAME nodes (13772edbbd, 577967799c, c64e793850). Export data also had to be position-faithful: exported constants and declarations got precise positions (b976859b47, 3124439b3a, a5b759aab8, 26e0e8a840, 1c439e6e37).

Subsequent evolution: package “height” (longest import chain) recorded in export data to order method sets deterministically across packages (07029254a0, 49ed4cbe85); fingerprints for the linker’s index consistency check first from a build id, then from a hash of export data (aefd99de0b, 7795523910 [dev.link]); column information added at ~4% export-size cost, though importers like go/internal/gcimporter only read it (95b8cbfee9); from 2021 export began to include enough information to avoid retypechecking inline bodies (1129a60f1c), field notes (c7d708e42e, e12b0afa54), ABIs (67d565d281) and closures (1760d736f6, 5f3dabbb79, b98ce3b606, eb433ed5a2).

Design. The classic algorithm for ordering package-level variable initialisation did not match the spec (issue 22326). Go 1.13 rewrote it (5d0d87ae16): dependency graph over variables and functions (references via function bodies), emission in spec order, and cycle diagnostics that include referenced functions “like go/types does”. The reporting algorithm later exploded exponentially on real programs (explores all paths through call graph; 600x slower than Go 1.12, 2+ minutes for a 7,000-line program), fixed in 1.16 (6598c65646). In 1.17 the logic was reworked again by moving the init pass earlier: fninit is called earlier (f4936d09fd), 68e6fa4f68 fixes package-initialization order after the IR change, 7fde0d2b50 removes Initorder/Offset Node fields used by initorder, and pkginit becomes its own package (3d8a3cb06b).

Design. types2 is the compiler’s copy of go/types (same code, different AST: cmd/compile/internal/syntax). In Go 1.25 the checker stopped using core types: 7194caf11b, 6adf08f747, 4b1ac7bbfe, 26ba61dfad, 05354fc3b4, 7e81bcf39f, e5d3ece35d, and the replacement helper commonUnder (8b7e376e71, with an optional condition callback and an error cause that is only allocated on failure). commonUnder is a type-set-wide “all underlying types are identical” test. 1.24 had already moved underIs/coreType/coreString onto typeset iterators (1e5a72e980, 681751a1fe); 1.26 made typeset itself return an iterator (6b32c613ca).

Design. A *Named is either a declared type or an instance of one. Instances carry an inst record (origin, type arguments, a Context) and are expanded lazily: the underlying type and methods are substituted via subst only when needed. 1.18 started with an instance helper type and InstantiateLazy, then merged instance and Named (473e493d18, 166b691b65, 3100f54f20) to avoid a sanitization pass. The public API settled as Instantiate(ctxt, orig, targs, validate) returning an error (fc27eb50ff, 69d8fbec7a, 22e9265467, c7e354d9d1), with an opaque Environment renamed Context (bd97763577, a1f6208e56, 99d5d8ab6b). Context dedups instances by a type hash (30e9bfbcef, 437362ccec, 489f58779c, 633d8c120b). Hash collisions are resolved with Identical (a52e4b9c7e, 313cae3861) and signatures are deduplicated as well (a17a21c190). TypeHash was exported, then unexported (9fc28892cb, 8b66b3d49f).

Methods of instances are instantiated lazily, and from b66bc0a9d5 each method is independently lazy through a methodList guarded by per-method sync.Once, because “method signatures can introduce a significant number of edges into the type graph”. Later versions replaced Named.once with a monotonic state field and Named.mu (846f971daa, 1323b0e8f0, 02e69cfa96). Named type identity stopped being canonical, so method-set computation looks up types by Identical rather than pointer (f088f4962e), and Var/Func objects got Origin() (1170771074). An invariant keeps instances created during expansion in the same Context as the expanding type, so infinite expansion chains terminate on a previously seen instance (47e34ca533, ensure that named types never expand infinitely).

Type inference and unification

Span: Go 1.18 → Go 1.27 · Status at HEAD: new unifier-centred inference since 1.21; reverse inference, interface inference and untyped-constant defaulting shipped; assignment-context refinements in 1.27

Design docs & discussion

Design. Function type inference infers missing type arguments from (1) typed function arguments, (2) constraints, (3) untyped constants’ default types. In 1.18 it had two entangled phases (function argument inference, “FTI”, then constraint type inference, “CTI”) around a unifier with per-parameter slots. Pitfalls were handled with local fixes: masks against infinite recursion (435718edd9, partly reverted by 5780be401f), renaming of type parameters when the call is self-recursive (93b5309f0a; made unconditional by e738a2f19b, because the heuristic for self-recursion was wrong when function literals clobbered the environment), and unification of core types for unbound type parameters (f03ab0e014, which has a kill switch enableCoreTypeUnification).

In 1.21 Griesemer rewrote it as infer2 (683b2c4600), made the only implementation by 93f5335be9 and 969c3ba839 (“use new type inference algorithm exclusively”), and deleted infer1 (d81ae7cfc7, 997dbcf6ba). The new algorithm uses one unifier holding a type parameter => type map; it is fed all facts, order-independently (8fd6cc8bb5 removes argument sorting): (1) unify every typed argument with its parameter; (2) unify each type parameter with its constraint’s core type (or, with 726d898c92 in 1.24, also its methods) iterating until fixpoint; (3) only as a last resort apply the default type of untyped constants; (4) substitute inferred types until no type parameters remain. Unification now has modes: assign for parameter passing (inexact at top level) and exact for component types (ee402e9882 removed the need for the recursion depth limit introduced for #59740). The unifier also detects no progress (4cba0bd74a), handles pointer identity (35a4d1b3bc), and uses a map instead of a type-parameter list (4b7f7eef3f).

Generics via GC-shape stenciling and runtime dictionaries

Span: Go 1.18 → Go 1.28 · Status at HEAD: shipped design since 1.18 (first built on the old typechecker/-G=3, reimplemented on unified IR in 1.20); shape sharing is still “underlying type, pointers collapsed”, with occasional shape/reshape bug fixes through 1.27

Design. A generic function F[T] is compiled once per GC shape, not once per type argument. A shape type (package go.shape, types.IsShape/HasShape flag) is the type argument’s underlying type; all pointer types collapse to a single go.shape.*uint8 shape. Shape types are named with a go.shape. prefix (b730a26729, 137543bb93), integer signedness is kept distinct because shift semantics differ (8767b87ab5), and since 1.22 the symbol uses a hash of the underlying type’s link string when that string would be absurdly long (8c1349baf7). The shaped instantiation takes a hidden first .dict parameter (7b876def6c added the dictionary argument, before the receiver). The dictionary is a read-only global [N]uintptr holding everything the shaped body cannot know statically: *runtime._type for every type derived from a type argument, sub-dictionary pointers for callees (ddb09af1b8, f503740ccf, 6dec18cc75), itabs for conversions to non-empty interfaces (02c0172500, ac3ba97907), and method-expression closures for calls through bounds (7fc38802e1, f326964824, fc72b7705d). F[int](...) becomes F[go.shape.int](&.dict.F[int], ...); the non-shaped F[T] is a wrapper.

Conversions of shaped values to interfaces, .(T) assertions and type switches use ir.DynamicType/ODYNAMICDOTTYPE (f4f503e0a3, ca3c6985cd, 0e2f1abf5b) so the type comes from the dictionary instead of the (shape) static type. Dictionary format is computed on the instantiated function after transforms rather than on the generic one (59a9a035ff), because the set of CONVIFACE nodes depends on which type arguments are interfaces. Instantiated functions are DUPOK so the linker drops duplicates (7160e32529), and dictionary/method-set survival under linker pruning needed explicit handling (2fe4b14795, 301f6c8019). DWARF carries dictionary entries (72bb8185b5), and ir.Name.DictIndex tells Delve where a derived-type local’s rtype sits in the dictionary (07cf24bdfe).

A non-obvious cost: the interface conversion the compiler inserts to call a method through a type-parameter bound would heap-allocate the data word for non-pointer-shaped types; e550c30545 removed that allocation (later reverted in 3f69cc7d77 when it proved wrong and replaced by method-expression closures stored in the dictionary).

Unified IR: one serialization for noding, stenciling, inlining and export

Span: Go 1.18 → Go 1.28 · Status at HEAD: the only frontend since 1.21; internal/pkgbits + noder/{writer,reader,unified,linker}.go; UIR at version V4 (V5 method indices added in 1.28 dev), documented with a formal grammar in 1.25

Design. Before unified IR, a function body was copied four times by independent implementations: noder (syntax -> IR), stenciler (generic IR -> instantiated IR), inliner (backup copy + inline copy with renaming) and importer/exporter. 79cd1687e6 replaces these with a pipeline syntax -> types2 -> writer -> bitstream -> reader -> IR: the writer (noder/writer.go) walks the syntax tree plus types2.Info and emits a byte-oriented, section-based (strings, positions, packages, names, types, objects, bodies, …) export-like encoding; the reader (noder/reader.go) rebuilds IR from it. The same reader is used to create the current package’s functions, to read imported inlinable bodies on demand, and to read other packages’ export data for types2 (importer/ureader.go), so the “export format” and the compiler IR are the same thing. Lazy loading of types and objects, re-export of inlinable bodies without parsing them into IR, “sync” markers for debugging, and a quirks mode that matched old output byte-for-byte (859d903b06, later removed) were part of the first CL. The author estimated +6 kLOC / -14 kLOC once old code was gone, and claimed it supported inlining of more code (local types, type switches, closures) than the old inliner “without requiring any new code”.
