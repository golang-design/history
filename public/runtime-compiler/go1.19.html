Go 1.19

Part II · master 936c7fbc1c..d723df76da · 735 in-scope commits

Soft memory limit (GOMEMLIMIT) and GC CPU limiter. Scavenger index redesign. Jump tables for switches. riscv64 register ABI. linux/loong64 port. Unified IR gains full generics support.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Runtime: memory allocator and garbage collector (Go 1.18–1.28)

  • GC pacer redesign — Done: user-visible the old pacer and the experiment were deleted (3334afd760). To support the memory limit, the goal and trigger are now computed on demand from current inputs, with a new triggered field recording where a cycle actually started (129dcb7226). The maximum-trigger computation was rewritten to match its intent (473c99643f), and trigger math moved to integer shifts (973dcbb87c). gctrace now prints the correct goal (a6c75aa5c3). A late regression came from making alloc counts truly monotonic (79db59ded9), which also made heapLive monotonic and caused small-heap memory growth; it was partially reverted to a “non-monotonic overestimate” (1ebc983000), and the pacer went back to the precomputed trigger (85a482fc24). Left open: “in the future we should consider moving away from such a history-sensitive smoothing function” (85a482fc24).
  • Soft memory limit and GC CPU limiter — Done: user-visible the limiter was added and turned on unconditionally, along with a feature flag for memory-limit code (01359b4681). Then came, in order: limit plumbing (986a31053d), mappedReady (4649a43903), sys* wrappers (f990b0f1e8), alloc/free counts (85d466493d), heapFree (d36d5bd3c1), stats moved into gcController (375d696ddf), the dynamic goal (129dcb7226), the limit-derived goal (7e4bc74119), allocator and scavenger enforcement (b4d81147d8), the exported runtime/debug.SetMemoryLimit (f01c20bf2b), and the GOMEMLIMIT parser accepting B/KiB/MiB/GiB/TiB (0feebe6eb5). Limiter refinements: a private assist-time pool (2eb8b6eec6), idle-mark and total-idle accounting (08d6c4c2b9, 54bd44e573), cancelling assists (1f0ef6bec7), windowed accounting (d7941030c9), and a /gc/limiter/last-enabled metric (cfccb5cb7c). Left open: the 61-bit timestamp can produce “hiccups” when the top bits change (d7941030c9). Thrashing with idle mark workers disabled (periodic GC) is not handled (08d6c4c2b9). The fixed 1 MiB headroom later caused eager scavenging (#57069).
  • Scavenger redesign — Done: scavenger refactored into a testable scavengerState (d29f5247b8); chunk-index redesign (91f863013e, ccb798741b); memory-limit goal and allocation-time scavenge assist (b4d81147d8); physical-page-aligned allocations restructured so scavenged-bit accounting stays exact (b58067013e). Left open: finding work can mean iterating “across the whole heap”, giving “worse overheads for memory limit scavenging” (91f863013e).
  • Finalizers, runtime.AddCleanup and the cleanup queue — Done: the finalizer reflectcall frame did not include the register-ABI spill slot and could clobber the caller; fixed (58804ea67a). Left open: nothing noted.
  • Mark worker scheduling and GC work queues — Done: periodic-GC idle-worker cap (e1b5f347e7); idle workers disabled when a dedicated worker exists (d8cf2243e0); merged wbuf checks in tryGetFast/putFast (86c8075675). Left open: idle workers are still “necessary for GC progress” when only fractional workers exist (e1b5f347e7).
  • Address-space layout, tagged pointers and the mem.go layer — Done: sys* wrappers and consolidated docs (f990b0f1e8). Left open: nothing noted.

Other changes

  • BoringCrypto GC-aware cache internal — boring.Cache, a fixed-size concurrent map from unsafe.Pointer to unsafe.Pointer cleared every GC, replacing a hidden struct field; later factored into crypto/internal/boring/bcache (a840bf871e, e845f572ec, 8f9bfa9b7b).
  • 64-bit atomic field alignment test internal — (6b6813fdb7).

Scheduler and concurrency

From Runtime: scheduler, timers, channels, locks and synchronization (Go 1.18–1.28)

  • Timer rewrite: per-P timer heap, timer.lock, and GC-able synchronous timer channels — Done: timerModifiedEarliest cleared when the last timer is deleted (c006b7ac27). Left open: nothing noted.
  • Scheduler core: spinning Ms, work conservation, stealing, STW interaction — Done: work-stealing order randomness fixed: with GOMAXPROCS=12 only 4 coprime strides existed so position and stride were correlated; now chosen independently (510ad4561f). Scheduling decisions from schedule moved into findrunnable so any M in findrunnable can become a GC worker or trace reader and handoffp sees all work sources (fixes #44313, #39004) (13b18ec947). runqgrab yields instead of sleeping on OpenBSD/NetBSD (226346bb76, b93ceefa7b). Goroutine-profile STW reduced to fixed bookkeeping with a barrier in the scheduler (52bd1c4d6c). Left open: lost-wakeup race when a non-spinning M drops its P.
  • Asynchronous preemption: extended register state — Done: loong64 asyncPreempt (740b0ebb76); arm64 uses stp/ldp (2e9facbdd4). Left open: nothing noted.
  • sync package API evolution — Done: happens-before documented for sync, atomic, finalizers (a71ca3dfbd); Cond guidance (d42a48828f); semaphore-treap scalability tests (7bad61554e). Left open: nothing noted.
  • sync/atomic and runtime atomics — Done: user-visible typed atomics (ffe48e00ad). Left open: runtime still uses old API.
  • Runtime lock ranking — Done: partial order edge for trace/wbufSpans/mheap (482669db62). Left open: nothing noted.
  • Fast random numbers for the scheduler — Done: fastrand64 (ebe1435fbb). Left open: nothing noted.

Other changes

  • Regabi condition cleanup internal — d8bee94be2.
  • Closed channel receive fast path internal — ca7c6ef33d.
  • Goroutine profile with barrier internal — race annotations (209942fa88), STW reduction (52bd1c4d6c).
  • Syscall via RawSyscall on Linux internal — landed and reverted (64e69d3925, bb004a179a, aac1d3a1b1).
  • Misc internal — Pool.Put redundancy removed (507a44dc22); fastrand64 use in net (a4bbcd4b1f); faketime jump uses pidleget (13f6be2833); atomic alignment docs (0eb7051aad, 69bb7c6ef5); m.procid alignment on 32-bit (ea7e3e3c0f); execution-trace profile prefers curg (7b1f8b62be).
