Early loaders 5l/6l/8l and the shared src/cmd/ld (2008–2011)

Span: Go 1.0 → Go 1.0 · Status at go1.17: replaced by the C-to-Go converted linker in 1.5 and by cmd/link thereafter → continues as Relocation-free pclntab and funcdata (offsets instead of relocations) and Per-platform object formats and internal linking (Mach-O, PE, XCOFF, wasm, ppc64, riscv64, loong64) (1.18+)

Design. The Go linkers started in June 2008 as one C program per architecture (6l for amd64, then 8l for 386 in 7d443bb67a, 5l for ARM imported from the Inferno distribution in db3a21d7c6). Each had its own obj.c (object reader), asm.c (container writer), span.c (instruction encoding and span-dependent jumps), pass.c (stack-split insertion, branch following) and optab.c. The object format was the Plan 9 style .6 file: text-ish records with a $$ delimited export-data section (4958d41d3b changed the delimiter to \n$$) followed by instruction records. Libraries were read through libbio (a570eaabcd, bfc70d0f0a).

Over 2009–2011 the portable parts were progressively hoisted out of the three copies into src/cmd/ld: Go-specific loader code (b87e3e8b7f, “ldbody”), portable object and library bits (c2874976e4), the XputY writers (fb55941539), asmlc (30edda690f), symbol table and ELF generation (d37c572ad5, 1.1: one asmbelf in elf.c replacing three nearly identical copies, plus a single genasmsym). A new flag parser matching package flag semantics replaced the C-style clustered flags in the linkers and compilers (cbbc6a102d, 1.1); -V (b4fb00b69b), -L (48974f553d, e6bc5bf5af), -r/rpath (e6443f6255), -I interpreter (9040da9e40), -B build ID (32316bba5b), -X string-variable setting (267f56e10b parsed, e3755434b8 implemented), -w (64b497c62a), -s eliding the Go symbol table (10d0dffd76) and -H as an enum with symbolic names (0cf6f8c096) appear in this period.

Layout changed in several steps. Initially the linker laid out the whole program as one instruction list; 9c20485268 (6l) and eb6f683691 (8l) switched to function-at-a-time layout and reworked span-dependent jump resolution: forward jumps resolved at their targets via a comefrom list, jumps marked small or big with only small to big transitions, so most functions need two passes and the maximum dropped from 5 to 3. 01df088f8d split address assignment into a separate pass (code laid out before data) and e5e9211071 introduced sub-symbols, symbols laid out inside a larger one but addressable directly (first used for the Mach-O pointer array). Archive loading changed from symbol-driven to loading whole archives (49084db386), earlier having been tuned with a heuristic (a3c4faf83f) that was dropped again in favour of letting the dead-code pass discard unused objects (fc8dca9dac). Duplicate loading of the same object was stopped (69e244a104), only one object file (package main) is accepted on the command line and the rest are pulled in via the package path (3b1a0355b6, 00f4c6a1b5), and the link fails if the top-level package is not main (11e254e62c).

Design docs & discussion
  • design doc Go 1.2 Runtime Symbol Information cited in this thread's commits
  • motivating issue #6853 all: binaries too big and growing referenced by 4 of this thread's commits

Design. The binaries carried two tables the runtime and debug/gosym read: gosymtab (Plan 9 style nm symbols, used for names) and gopclntab (per-function pc-to-line and pc-to-SP-delta tables). Early on they were loaded by a special mapping to a high address (0x99000000, “pad Go symbol table out to page boundary” fe43325b30, “move mapped symbol table lower in memory” 8ec9ffc742). 19fd5c787f (2010) turned both into ordinary rodata symbols so the information is available on systems that cannot do the magic load (NaCl, ARM QEMU, Linux without highmem) and removed Windows special cases. In 2011 the ELF overlap of sections that owned the same bytes was fixed so strip was happy (cf143e9dbf, ba2e3af177).

A large share of binary size was symbol names for compiler-generated data. 7a09a88274 (2011) deleted the names of type.*, string.* and go.string.* symbols from the symbol table, aggregating them into contiguous blocks, shrinking godoc from 9.15 MB to 4.29 MB (3.40 MB without DWARF). Go 1.1 changed encoding for host-linking: 4e2aa9bff0 stored symbol values as native-endian (the table begins with a magic saying which) so a host linker can fill them via relocations, and c8dcaeb25d repacked the table with pointer-sized host-endian addresses and varint-encoded other values.

Go 1.2 is the structural change: “new in-memory symbol table format” (5d363c6357, design go12symtab) and a “contiguous pcln table” (c3de91bb15). pclntab became a single table with a header, a sorted functab of (entry pc, funcoff) pairs, a Func record per function containing offsets to pcsp/pcfile/pcln/pcdata tables, a file table and a funcdata array. GC information moved from pseudo-instructions in the instruction stream to FUNCDATA (48769bf546), args pointer bitmaps (4e0a51c210) and accurate args/locals sizes in bytes (f466617a62) were added. In 1.3 liblink’s new object reader/writer introduced a pcdata iterator and removed the linker’s “line number stack” and “path fragments” (a9f6db58ce). In 1.5, 63116de558 added a build-time lookup table (the later findfunctab) to find the function containing a pc, 13.35% faster stack copy and ~0.5% of text size, with a 16-byte minimum function size; 6dd31660b0 and 214c7a2c43 stopped putting container symbols in functab/symtab.

Design. In the earliest linkers, pass.c inserted the prologue that calls morestack for segmented stacks (“segmented stack” 1f6828bcdf, b987f7a757, then 5l support 83632c7359, 1ac2cfc720 with argsize passed). Design. The first linkers tracked reachability with a pass that discarded unreferenced symbols and then (after 9cba9c8890, “eliminate dead code, not just the symbols”) really removed their code from the instruction lists; 8d8225d529 turned GC of unused data/code back on. 7b29dbb866 stopped emitting unreachable data symbols. fc8dca9dac replaced the heuristic of not pulling objects from archives purely for their init function with “pick up everything and let the dead code/data eliminator throw away the parts that weren’t useful”. Line numbers survive removal of dead functions (47e27758db, fda0e78b23). The Go 1.3 skeleton of the new Go linker had a worklist-based dead.go (7dcc652f10).

The substantive 1.7 change is 862b9ddda7: previously all methods of reachable types were kept to support reflect.Value.Call. The linker now looks for use of reflect.Value.Call (and Method, e2836935bb) and, if absent, prunes methods: a method is kept if it is directly called or matches the signature of a method of some used interface. Whether a method body is kept is decided by the relocation from the receiver’s *rtype to the method’s *rtype; d06b0db5bd also prunes the funcType, and 44d3f89e99/f2772a4935 removed some method type data (second method type computed at runtime). The go.plugin.tabs symbol is marked reachable only in plugins (67b2927990) and DWARF function symbols marked reachable (aad06da2b9). 6f31abd23a (1.8) added R_WEAKADDROFF, a weak variant of R_ADDROFF used for the ptrToThis field so the pointer-to type is kept only if otherwise reachable.

New object file format and the loader (dev.link)

Span: Go 1.14 → Go 1.16 · Status at go1.17: done; the linker reads only the indexed object format through cmd/link/internal/loader, sym.Symbol is gone, and the format gained a weak-reloc bit and 16-bit reloc types in 1.17 → continues as Relocation-free pclntab and funcdata (offsets instead of relocations) and Type, itab and typelink layout (.go.type section, relro rework) (1.18+)

Earlier history: liblink, the object file format and the move into the compilers (Go 1.3 → Go 1.9)

Design docs & discussion
  • design doc (PUBLIC) Building a better Go linker listed in Go: A Documentary

Design. Through Go 1.13 the compiler wrote an object file whose symbols were identified by name strings and which the linker (objfile.Read) expanded eagerly into one heap-allocated sym.Symbol (with []sym.Reloc, auxiliary fields, DWARF autos, etc.) per symbol. The dev.link branch replaced this with a new object file (“goobj2” in cmd/internal/goobj2, renamed back to cmd/internal/goobj once the old one was deleted) in which every symbol is addressed by an index: a defined symbol is (package index, local index), referenced non-package symbols and builtins use pseudo-package indices (PkgIdxNone, PkgIdxBuiltin, later PkgIdxHashed), and the file is laid out in blocks (header, string table, per-symbol definition array, reloc array, aux array, data) so the linker can mmap it and read only what a pass needs. The reader, NewReaderFromBytes, works directly on the mapped bytes.

The linker side is the loader.Loader. It assigns each symbol a global loader.Sym index in object order (package DAG order), keeps a local-to-global array per object, and tracks overwrite (a dupok or contentless definition replaced by a real one) and ABI aliases. The first design gave every appearance its own global index with a redirect map; 8e2b5d3e71 made the index unique per symbol (N-to-one local-to-global mapping, a global-to-primary-local array, no overwrite map) and 2f22143cd5 stopped reserving index space for dups so there are no holes. Package-defined symbols were added first so they need no name lookup (b0275bfbf4). Symbol metadata (type, value, size, alignment, section, attributes, ELF type, dynimport, plt/got, Gotype, compilation unit, outer/sub relationship) lives in loader side arrays and bitmaps instead of struct fields; 24814e2147 enforced a single level of “outer” symbol. Symbols created by the linker itself are “external” loader.Syms (07914eda40, b720014743 SymbolBuilder, later MakeSymbolUpdater) that carry a payload (extSymPayload) until the end of loading.

Costs of the old design were the motivation: memory (a full sym.Symbol for every symbol even if dead), startup time, and GC pressure. The new design lets dead-code elimination run on indices before any contents are loaded, and every later pass materialize only live symbols. Further format changes tuned locality and self-description: StringRef was changed to {len, offset} so a string header is two adjacent uint32s (ff29f97437), referenced symbol names were written to the file so nm/objdump are self-contained (73dd74a9fe), content-addressable “hashed” symbols were added (see the pclntab thread) (27342e5bd9, 4f217d5aaa), and in 1.17 the relocation type became uint16 with a separate weak bit (f901ea701d, 414fa8c35e).

Wavefront conversion of linker passes to the loader; sym.Symbol removal

Span: Go 1.15 → Go 1.16 · Status at go1.17: done (all passes run on loader.Sym; cmd/oldlink gone from the story) → continues as Relocation-free pclntab and funcdata (offsets instead of relocations) (1.18+)

Design docs & discussion
  • design doc (PUBLIC) Building a better Go linker listed in Go: A Documentary

Design. The linker is a sequence of phases (load, deadcode, symtab/dodata, address, reloc, asmb, DWARF, …). Rather than convert everything at once, the dev.link team moved a “wavefront”: everything before it works on loader.Sym, everything after still on *sym.Symbol, with LoadFull / PropagateLoaderChangesToSymbols shims (3fa98a0436, 7055f01e12) copying state across. Each CL pushed the wavefront one pass later (“move the wavefront past addexport()”, 84111acd35; “past address”, dc83274c95), and removed *Link dependencies from architecture hooks by introducing Target and ArchSyms (e9056a6a73, b9642cbb8d, 4ab7ab54b0, cb4c84bd9a, bf5dc7af0f) so that relocation can be made thread-safe. The dodata (data layout and section assignment) was split up and rewritten on the loader (a6a8974a5a, 817bd10cae, 941de9760b) and enabled per architecture, from darwin/amd64 (b2fde1098a) via plan9/wasm (f9ed846a46), ELF arm/arm64 (d5c9327628), MIPS/RISCV64 (aa74fce005), s390x (5ea431fb63), ppc64 (8bd7c01417) and darwin/arm64 (512a0219ef), until the old dodata could be deleted (98e3fdab3e). Later the relocation pass (76c6cce116, external linking 095d2a4532), asmb2 (1adae7fe76, then per-OS in 1.16) and the architecture archreloc functions were converted, one architecture per commit.

Design. Three families of work. (1) Avoid memory: shrink hot structs (Reloc moved cold fields to a lazily initialised side struct, 8ef45cf60b: kube-apiserver inuse_space 1240MB to 1123MB, max RSS under GOGC=5 2.05G to 1.83G; Symbol fields moved to cold sections in 1.12: 09df9b06a1, 2975914a1a, f78cc1324a, dd9e81f678; Reachparent as side table 32bc0976f9; Dynimp strings split f00bfb385b), read-only mmap backing for symbol-name strings and object data (9ac471a87d, dbe32284ff), then the loader’s lazy loading. Streaming external relocations were a memory trade: instead of converting Go relocations into an in-memory external format during relocsym and writing them in asmb2, the writer emits ELF/Mach-O records straight from the Go relocations into the mmapped output (987ce93824: Asmb2 alloc 66.8MB to 8.2MB; 59a702aa6a; 88382a9f97 amd64 where Asmb2 became 23% slower but Asmb -84% alloc; then 386, arm64, MIPS, s390x, arm, windows and ppc64 with 936a2d6966, bf1816c7b7, ed6b8af509, 71e2133304, e4a3e57f47, 9d22325681, and the old path deleted 4b3cfcee58). External relocations were first stored in Reloc2 format (6e3bde5f30) then as an index into the original reloc (cdfff4d25a). Generator symbols (f033e23414) are real symbols with size but no data; a function fills the bytes during Asmb, so very large tables never occupy heap (used for pclntab pieces, see that thread).

pclntab, funcdata and pc tables

Span: Go 1.12 → Go 1.17 · Status at go1.17: pclntab split into runtime.pcheader, funcnametab, pctab and generator-built tables; still relocation-based → continues as Relocation-free pclntab and funcdata (offsets instead of relocations) (1.18+)

Earlier history: Go symbol table, pc/line table and function metadata (gosymtab, pclntab, findfunc) (Go 1.0 → Go 1.5)

Design. Up to Go 1.15 the linker built a single runtime.pclntab symbol in pcln.go: header, function table (ftab, pc to func offset), each _func record, function names, file table and the pc-value tables (pcsp, pcfile, pcln, pcdata) concatenated into one big heap symbol, with strings and file names deduplicated but renumbered per link. Memory and time were dominated by this symbol. Jeremy Faller’s 2020 plan (documented in ba9c639470 as an “improved format” doc) broke the table into independent pieces that no longer need rewriting: header, function names, file names, pc tables, and per-function _func data, each emitted late in the link from generator symbols and addressed by offsets rather than copied.

Mechanisms used: (a) deduplicate pc tables - first by a cache keyed by content inside the linker (d79aea6b96, 33% hit rate during make.bash, binaries about 1% smaller), then by making pcdata content-addressable symbols in the object file (5387cdcb24); (b) hashed/content-addressable symbols and PkgIdxHashed (27342e5bd9) to dedupe across packages; (c) moving per-function derived facts into the compiler/assembler so the linker does not need to load names (89cf569a45 FuncID, e4e1c6a7af compilation-unit index in Func); (d) per-package file tables used directly as file indices to avoid renumbering (9bdaf99966, 9ae8f71c94); (e) generator symbols filling bytes during Asmb (f033e23414).

Dead-code elimination and method pruning

Span: Go 1.10 → Go 1.17 · Status at go1.17: index-based deadcode with UsedInIface/R_USEIFACE/R_USEIFACEMETHOD method pruning, weak itab edges and reflect-aware tracking → continues as Dead code elimination and reflection-aware pruning (1.18+)

Earlier history: Dead code and data elimination (Go 1.0 → Go 1.8)

Design. deadcode.go does a flood from roots (_rt0_*, runtime.main, init tasks, exported cgo symbols) over relocations. Methods get special treatment: a method of a reachable type is kept only if it can be called indirectly. The original rule matched type methods against all methods of every reachable interface type (by name+signature string), plus R_METHODOFF-based tracking for reflect.Type.Method/MethodByName (which disable pruning entirely when reachable).

The dev.link rewrite ran on loader indices (8a9be4921a, method tracking 7d6f79e617, reflect.Type.Method d6535415fb, relocation hooks 376ef734a7, field tracking 219922e95b, -dumpdep restored c6621d9241) with a work queue ordered by a min-heap because global indices follow package DAG order (36dbdbe9bd; hand-written heap 7179e426e2). In 1.16 Cherry Zhang tightened the semantics in several steps: compare the method name and type descriptor rather than strings (e4d6bfdbdf); compile marks type descriptors converted to interfaces and the linker only considers methods of such UsedInIface types, propagating the mark to “child” types reachable by reflection (95848fc5c6: cmd/go -5.1% bytes) and through method descriptors (789d77a87e); the mark is applied only when the converting code is reachable via a new marker relocation R_USEIFACE (af18bce87c: cmd/go 13.6MB to 13.47MB); used interface methods are marked by R_USEIFACEMETHOD, so only called interface methods keep matching concrete methods alive (39dde09126); itabs reference methods weakly so unused ones can be pruned (e8700f1ce6, 1.17); unreachable methods get offset -1 (0ab72ed020) so a bug fails fast.

Design. Design. The pclntab (cmd/link/internal/ld/pcln.go) is the linker-generated function table that the runtime and debug/gosym read. Historically every function entry, funcdata pointer and stack-object pointer was a relocation, which cost linker time and, for externally linked or PIE binaries, dynamic relocations (and forced the table into relro). The thread converted each such pointer into a 32-bit offset from a well-known base symbol (runtime.text, go.func.*, go.funcrel.*) so the data becomes position independent and relocation-free.

On the object side the same logic removed per-function side blocks: PCDATA moved from a separate object-file block to ordinary aux symbols (SymPcdata-style aux in cmd/internal/goobj), funcdata offsets were dropped from the object file and replaced by aux symbol references, and symbol alignment moved into the object writer so the linker no longer computes it. The result is a smaller goobj format and a linker that only emits plain bytes for these tables.

By Go 1.26 the process was completed for the header and the surrounding runtime tables: the only remaining relocation (textStart in pcHeader) was dropped, the pclntab magic constants moved to internal/abi (shared by linker, runtime and debug/gosym), and funcdata symbols, runtime.findfunctab and the pclntab all share one .gopclntab section.

Dead code elimination and reflection-aware pruning

Span: Go 1.18 → Go 1.23 · Status at HEAD: done

Earlier history: Dead code and data elimination (Go 1.0 → Go 1.8) · Dead-code elimination and method pruning (Go 1.10 → Go 1.17)

Design. The deadcode pass keeps method sets alive only for types converted to interfaces whose called method names appear. Two hazards were handled: generic interface calls and reflection by name. For generics, a new relocation (R_USEGENERICIFACEMETHOD, later R_USENAMEDMETHOD b4c889b561) records that a method was called on a generic interface so implementations are kept. The compiler learned to flag Type.Method/Value.Method users as ReflectMethod, letting the linker drop its special cases for Method() and MethodByName(). Large unreferenced map variables are removed by the compiler making their init functions weak, with a linker pass after deadcode that redirects weak R_CALL relocations to unreachable map.init.* helpers at a no-op (mapinitnoop).
