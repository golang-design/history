Go 1.20

Part II · master d723df76da..83f8688915 · 953 in-scope commits

Unified IR becomes the default frontend with real dictionaries. PGO preview (hot-call inlining). Coverage redesign. Arenas experiment. 1-bit heap bitmap. Pacer smoothing via moving average. clear is type-checked here but gated to go1.21.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Runtime: memory allocator and garbage collector (Go 1.18–1.28)

  • GC pacer redesign — Done: the PI controller was replaced with a 2-cycle moving average using the actual trigger; the PI controller moved to mgcscavenge.go, its only remaining user (41795528b0). gctrace prints lastStackScan instead of the max (56bdf7f7d9). Pacer fields were converted to atomic types (see Other, Go 1.20). Left open: right after a phase change the average lags, which can cause a transient rise in assists (tile38 WithinCircle, 41795528b0).
  • Heap bitmap rewrite and allocation headers — Done: 1-bit bitmap rewrite (b589208c8c). It was reverted for wasm/386 failures (ad0287f496) and relanded unchanged (6a9c674a09) after making the GC never scan noscan objects (cb13022a24) and initializing pointer bits for noscan spans for cgo/heapdump callers (a6e6b11e3a). Word-at-a-time bitmap processing (“~30% faster in heapBitsSetType”) landed, was reverted and relanded the same way (c3833a5543, e1a8e0e05d, e49e876455). Left open: “we should make the gcdata bitmap an array of uintptr … Similarly for the processing of gc programs” (6a9c674a09).
  • Scavenger redesign — Done: searchIdx used in scavengeOne to avoid N² behavior within a chunk (2caaad942e), and padding removed (f324355d1f). Left open: nothing noted.
  • Finalizers, runtime.AddCleanup and the cleanup queue — Done: user-visible documentation that finalizers on tiny (<16 B) objects may never run (80d487111b); atomic fingStatus (−5% Finalizer benchmark, bd5595d7fa); test cleanup (eaf0e3d465). Left open: nothing noted.
  • Memory arenas experiment — Done: user-visible runtime arenas (7866538d25) and the arena package with reflect.ArenaNew behind a GOEXPERIMENT (e0d01b8467); refactors (69fc74f3ee, 987f94fa03, 4c383951b9); a test skip (e72da1c15d). Left open: “A later CL can potentially export it” (7866538d25); it stayed experimental.
  • Allocation publication, zeroing and preemptibility — Done: the scanner reads freeIndexForScan (febe7b8e2a); an accidental submit of the alternative design was reverted (bed2b7cf41, 2b59307ac2); Malloc benchmarks fixed (7717ac151a). Left open: nothing noted.
  • Sweeper termination and pacing — Done: bgsweep heuristic (8451529e9a, “may be worth considering pushing this number higher”); unused sweepdata field removed (2df6c1abce). Left open: nothing noted.
  • Address-space layout, tagged pointers and the mem.go layer — Done: arenaIdx accessors made nosplit (506e690a26). Left open: nothing noted.

Other changes

  • GC controller and heap fields to typed atomics internal — about 20 conversions: heapLive, heapScan, stack/globals scan, bgScanCredit, mark times, dedicated workers, mSpanStateBox, mcache.flushGen, work.cycles, mspanset, pagesInUse (e76155614a, 3a9281ff61, 6e9925c4f7, e1b0da6144, 02fb9b8ca9, b8f4847d6f, ba89d59a3a, 9463638ca8, fe406c8b11, dcd10375bc, 014f0e8205, a25a34abe9, 28e388589b, d61ffe8b6c, 5a37965495, f1b7b2fc52). Manual alignment padding was removed as a result (a52f4952cb, e28cc362a8, 1c59199c91), and the cache-line padding formula fixed (f15761b50b).
  • runtime/internal/sys.NotInHeap internal — replaces the //go:notinheap pragma with an embedded marker type (a719a78c1b).
  • Write-barrier-enabled pointer atomics internal — UnsafePointer.Store/CompareAndSwap and Pointer[T] with barriers (9fedc481ea).
  • GC bookkeeping fixes internal — userForced set under gcsema (6f7c9ea855); traceGCSTWDone only when tracing (8befe0e408); unused gcmarknewobject parameter removed (51c34e2f0b); _g_→gp renames (5e8d261918, 222799fde6); getStackMap as an stkframe method (b91e373729).

Scheduler and concurrency

From Runtime: scheduler, timers, channels, locks and synchronization (Go 1.18–1.28)

  • Timer rewrite: per-P timer heap, timer.lock, and GC-able synchronous timer channels — Done: timer fields converted to atomic types: p.timer0When, p.timerModifiedEarliest, p.numTimers, p.deletedTimers, timer.status (e1fd51e076, bb5d656a3a, c82bbc0e8e, 6e74c4116a, f78efc0178); schedt.pollUntil likewise (0fc774a68f). Left open: the timer state machine itself is still CAS-based.
  • Contended runtime-lock profiling (mutex profile for runtime-internal locks) — Done: user-visible /sync/mutex/wait/total:seconds runtime metric (63ceff95fa); wait reason for goroutine blocked on a mutex made specific (a2c396ce00, 686b38b5b2); mprof locks split (1.19, 89c0dd829f1.19). Left open: runtime-internal locks invisible in the profile.
  • Scheduler core: spinning Ms, work conservation, stealing, STW interaction — Done: sched.needspinning: if work submission (wakep, injectglist) finds no idle P it sets the flag, and a non-spinning M about to drop its P rechecks it and becomes spinning instead; fixes a worst-case deadlock when injectglist finds nothing as all Ps go idle (8cb350d69a). A long list of schedt fields converted to atomic types (see sync/atomic thread). goschedIfBusy yields if gp.preempt (50664c236f). bgsweep “low-priority” heuristic: don’t yield if idle Ps exist, sweep >=10 spans between yields, cutting trace events by 90% (8451529e9a). Left open: nothing noted.
  • sync package API evolution — Done: user-visible Map.Swap, CompareAndSwap, CompareAndDelete (395323c4d0); Map and entry use atomic.Pointer (b0144b3843, 7366b199c5); WaitGroup state atomic.Uint64 (ee833ed72e); RWMutex counters atomic (e509452727); Once.done atomic conversion reverted (b53471a655). Left open: nothing noted.
  • sync/atomic and runtime atomics — Done: the runtime-wide conversion (b464708b46, dd8cb66d0b, 5d7d50111f, 58a1dabfd1, 1eeef5d5b4, 88ef50e662, 3fbcf05d40, 951d2c657d, fa0e3bffb4, 3f65ddbfd3, 301ca7513f …); a revert for ncgocall (ef8414101f); user-facing hints toward typed API (0bd4710ca6). Left open: nothing noted.
  • Runtime lock ranking — Done: DAG generation, unused ranks deleted, trace locks moved to the leaf (2b8a9a484f, ddfd639408, f42dc0de74, cc8bac8835, 44ff9bff0c, c5be4ed7df). Left open: names of ranks lost.
  • Netpoller — Done: netpollWaiters, netpollWakeSig, netpollInited atomic (aab8d2b448, 901b9233e6 …). Left open: nothing noted.
  • Goroutine lifecycle and identity — Done: goid uint64 (dd8cb66d0b). Left open: nothing noted.
  • Fast random numbers for the scheduler — Done: loong64 wyrand (3a41094107). Left open: nothing noted.

Compiler frontend · syntax, IR, generics

From Compiler frontend: syntax, IR, unified IR and the generics implementation (Go 1.18–1.28)

  • Generics via GC-shape stenciling and runtime dictionaries — Done: Unified IR switches to real dictionaries: c9f2150cfb generates F[T]-dict globals, a F[T]-shaped function with .dict *[N]uintptr, and F[T] as wrapper; 38edd9bd8d is the shape-based stenciling commit (initially shape = underlying type, one dictionary per type, shared by all methods, deliberately so that a future “itab in closure register” scheme could find the dictionary; noted drawback: dictionary entries for pruned methods stay alive, possible fix by linker R_DICTTYPE/R_DICTUSE relocations). Left open: 5e0258c700 says shape rtypes are still used for runtime.newobject of heap-escaping variables and “longer term I would like to get rid of shape rtypes altogether”; no pruning of dictionary entries for dead methods.
  • Unified IR: one serialization for noding, stenciling, inlining and export — Done: package height dropped from the importer and symbol ordering (3a1f1e1575, 4b78ece3d7, df7cb59de4); dictionary logic pruned (29b07037b1); 0a6e1fa986/ddc93a536f/aa6a7fa775 fixes for shapifying recursive instantiations and reflect naming of local generic types; default-on via 833367e98a (author date 2022-08-09, internal/buildcfg: enable unified IR by default, GOEXPERIMENT=nounified becomes the escape hatch); runtime dictionaries and shapes (see generics thread); pkgbits EnableSync becomes a dynamic header flag (9371a65584, bumping the version; “drchase’s benchmarks show it isn’t as expensive as feared”); body pruning heuristic f995946094 (include all inline bodies for… with a simple heuristic rather than crawler-based pruning); e8afb29111 “temporary” readers to reuse storage; caa8e1f977 type-specialized ReadUvarint; 6b80b62fd1 rawReloc perf. 8ef8b60e18 stops handling type expressions as expressions. Middle end and SSA optimizer

From Compiler: middle end and SSA optimization (Go 1.18–1.28)

  • Profile-guided optimization (PGO): hot-call inlining, devirtualization, profile preprocessing — Done: user-visible Raj Barik’s initial implementation: pgo/graph.go and irgraph.go build the profile graph, and the inliner uses it (99862cd57d, #55022). Within the same cycle the heuristics were reworked:
    • Inlinability is decided by edge weight rather than node weight (fb4f7fdb26).
    • The hot threshold is a CDF over edge weights, not a fixed percentage (b07e845e76).
    • Calls are matched by line offset from start_line (bdd1e283a9, with a fix in 0409314db3).
    • Only the last two frames form an edge (6e0e492e12).
    • Defaults became 99% CDF and a 2000 budget, and the debug flags were renamed pgo* (1b03568ae1).
    • Supporting work: global state, label handling and per-location maps were removed for speed (ec0b540293, 204be97d24, d73885588a, 1a4cc091a9, a72e133422, 7e88b866f9, f187c6b08e, d9cc39b25c, 3f1bcc58b3); cross-package inlining was fixed (ada9385a5f); empty profiles are accepted (efe541d4e5); debug output and the missing-start_line hint were improved (e5d2814576, 64519baf38).
    Left open: the PGO package was still labelled “WORK IN PROGRESS”; the label was removed in 1.21.
  • Inliner: budget, closures, and the interleaved inline/devirtualize driver — Done:
    • With unified IR on, inlining fails gracefully (f2851c67fd) and more inlining is allowed, lifting the shape restrictions (52016be3f4).
    • Transitive inlining is deferred until the AST is edited (f983a9340d).
    • Cost discounts for encoding/binary appends and zero-offset field addresses (629c0b3a6e, 638c9aad5f).
    • A latent CalleeEffects issue was fixed (25d74f324d).
    • Coverage-counter updates do not count against the budget (4a459cbbad, 317f2a7df6).
    Left open: nothing noted.
  • Escape analysis: call modelling, closures, func-variable callees, and solver speed — Done: OITAB and OCHECKNIL are supported (0c2f87f23d). Left open: nothing noted.
  • Prove pass and bounds-check elimination: from poset relations to a dense limit table, topo-sorted walk, and division-aware proofs — Done:
    • The relation between x+delta and x (d2e0587f77), with 8/16-bit deltas (2addbf3f2a).
    • Bounds for strided-loop induction variables were tightened (af7f067e0d).
    • Signed relations for constant integer phis: −1.4% total size (d96eb826cb).
    • Bitwise OR (3680b5e9c4), reverted for compile time (a6ddb15f8f1.21) and relanded in 1.21.
    • An index out-of-bounds check in walkIndex was removed (98f5152368).
    Left open: the OR support was pending a compile-time fix.
  • Memory-op optimization: memcombine, dead stores, store-to-load forwarding, alias analysis, mem2reg — Done: more constant stores combined on amd64 (09932f95f5), plus store combining of values (e7307034cc). These were per-arch rules, the predecessor of the memcombine pass. Left open: each architecture needed its own rules, which the 1.21 pass replaced.
  • Lowering of builtins to memory ops: memmove/memclr/memequal inlining and generated equality — Done: the memmove optimization no longer trusts the destination pointer’s base type (e283473ebb). Struct-compare inlining uses a cost heuristic (6605686e3b). Left open: nothing noted.
  • Switch lowering: jump tables, type-switch caches, and switch lookup tables — Done: a better split for string binary search (69aed4712d). Jump tables are off when spectre retpolines are on (1eb0465fa5). Left open: nothing noted.
  • Static devirtualization and shape-aware type-assertion pruning — Done: fixed a unified IR devirtualization bug (d6294e00f0). defer/go calls are not devirtualized (c82304b712). OCALLMETH is desugared to OCALLFUNC within devirtualization (4f8bc6224b). Left open: nothing noted.
  • Range-loop and range-over-func lowering in walk — Done:
    • OFORUNTIL is no longer used (661146bc0b).
    • Range desugaring was refactored for unified IR, with RType fields for range assignments (0a503cf43a, d667be8831).
    • Careful pointer incrementing (8477562ce5).
    Left open: nothing noted.
  • Branch-free lowering: CondSelect-into-math and ARM64 CCMP — Done: CMOV disallowed when an argument is pointer arithmetic, which could be unsafe to speculate (c8057d8569).
