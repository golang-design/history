Go 1.3

Part II · commits first contained in tag go1.3 ^go1.2 (tagged 2014-06-19) · 599 in-scope commits

Contiguous (copied) stacks. Precise stack scanning on by default. Concurrent sweep, tiny allocator, 8K pages. liblink: instruction selection moves from the linkers into the compilers and assemblers, with a new object format. sync.Pool. NaCl and Solaris.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Memory management: GC and allocator (Go 1.0–1.17)

Concurrent sweep (3c3be62201), 8K pages, tiny allocator, specials replacing the finalizer table, parallel stack scanning.

  • Stop-the-world mark-sweep, then the parallel collector — Done: stack scanning moved into the parallel mark phase (0368a7ceb6); free-list objects kept marked-as-allocated so malloc/free need not touch bits (2d20c0d625, later restored after the GC rewrite as 187d0f67201.4); data race in GC fixed (b3a3afc9b7); GODEBUG=gcdead / allocfreetrace adjusted (1ec4d5e9e7); 3x fewer nanotime calls (95ee7d6414); markspan 2x on a NUMA box (acb03b8028); freeOSMemory now sweeps (e893acf184). Left open: sweep still inside the stop-the-world pause until the concurrent sweep thread.
  • Concurrent sweep and proportional sweep — Done: concurrent sweep with bgsweep and lazy sweeping (3c3be62201), MSpan.needzero instead of writing into span data (86e3cb8da5), races fixed (73a304356b, f8e4a2ef94, fed5428c4a, f8c350873c, 6e612ae0f5, ea87501750, 8d321625fd spans ending in wrong lists after split); stack shrink after sweepgen increments (e9445547b6). Left open: next_gc and heap accounting only approximate during the sweep (aea99eda0f fixed a runaway-memory case).
  • Stack scanning: conservative, precise by frames, stack barriers, hybrid barrier, async safe points — Done: stack scan in parallel mark (0368a7ceb6). Left open: gentraceback inefficiency.
  • Precise heap scanning: type information, the heap bitmap and GC programs — Done: lock-free settype (3b5278fca6), empty-string pointer fix (54c901cd08), pointer-in-interface scan same as pointer (68aaf2ccda). Left open: nothing noted.
  • Size classes, tiny allocator and mcache/mcentral — Done: 8K pages, tiny allocator, smarter slice growth, prefetch (e48751e217, 1fa7029425, bace9523ee, d176e3d7c5, d5a36cd6bb zero 2-word blocks in place). Left open: nothing noted.
  • Span lifecycle in mheap: free lists, treaps, first-fit and the page reclaimer — Done: specials hung off spans (020b39c3f3), span-corruption fix on split (8d321625fd). Left open: nothing noted.
  • Scavenger: returning memory to the OS — Done: FreeOSMemory sweeps too (e893acf184), Windows decommit failure handling (30b8af98c0). Left open: nothing noted.
  • Finalizers and span specials — Done: specials (020b39c3f3, e7d010a6a7, b039abfc3e), finalizer flakiness fix (241f63debd), leak fix in runfinq (b08156cd87), globals ignored (f4ef6977ff). Left open: nothing noted.
  • Memory statistics and accounting — Done: user-visible WriteHeapDump (fff63c2448), runaway-memory skew fixed (aea99eda0f), gctrace clearer (5539ef02b6). Left open: nothing noted.
  • Allocation-site profiling and GC debugging modes — Done: allocfreetrace (48279bd567, 3ec60c253d, 1ec4d5e9e7), efence improvements (c115cda22c, da1bea0ef0). Left open: nothing noted.

Other changes

  • sync.Pool user-visible — introduced (8c6ef061e3), cache policy of one element per P (8fc6ed4c89).

  • Comment cleanup in malloc internal — Removed an outdated comment and its related indentation. (c69402d82b)
  • More precise mprof sampling internal — Improved heap profile sampling of objects close in size to the sampling rate. (bf0d71af29)

Data structures and type metadata

  • Map growth, iteration order, overflow buckets and GC interaction — Done: evacuated bit moved into tophash (9aae6c1a8b), intra-bucket iteration offset (3be4d95731, 8454e2c287).
  • Runtime type descriptors: layout, shrinking and name encoding — Done: zero field in rtype (aad4609c08), precise reflect Value support (cbc565a801).
  • Interface values, itabs and type assertions — Done: interface data correctly typed (e9977dad45), scan of pointer-in-interface same as pointer (68aaf2ccda), wrapper for (interface{...}).F (f303921251).
  • reflect redesign: from string parsing to Type/Value structs — Done: Value rewrite for precise GC (cbc565a801), precise GC info for Call frames (2af7a26f1e), channel/select without iwords (873aaa59b7), Zero allocation fix (e7d899cba5), embedded unexported fields read-only (a8a7f18aea), MakeFunc variadic-argument fix (772d22885b), reflect Call of interface method uses the correct type descriptor (fcf8a77525), nil-map delete no longer panics (cb6cb42ede).
  • reflect dynamic types: ArrayOf, ChanOf, MapOf, SliceOf, FuncOf, StructOf — Done: correct map type generation (5bc1cef869).
  • reflect.Call, MakeFunc, method values and argument-frame GC precision — Done: callXX do not call stubs (85138da832), precise frame GC (2af7a26f1e), variadic MakeFunc fix (772d22885b), align call args on amd64p32 (ea7d801130), interface-method call type descriptor (fcf8a77525).
  • memmove, memclr, duff routines and pointer-write atomicity — Done: faster x86 memclr (da7cf0ba5d), Plan 9 uses unoptimized versions (8303a13bb8).
  • Slices and append: growslice, makeslice and string/slice conversions — Done: size-class growth, cap overflow check, 32-bit conversion overflow, m->locks (bace9523ee, 9121e7e4df, e1a91c5b89, 8afa086ce6).
  • Strings: concatenation, conversion and printing helpers — Done: no zero termination (9fa9613e0b), signed-zero printing (f574726f16).
  • Soft-float, 64-bit division and complex arithmetic helpers — Done: sqrt copy (ee7bb07a53), cross-function jump removal in vlop_arm.s for the new linker (7c17982f72).
  • C-to-Go conversion of runtime data-structure code — Done: goc2c (67c83db60d), errorCString as struct (7e639c0229).
