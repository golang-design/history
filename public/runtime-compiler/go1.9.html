Go 1.9

Part II · commits first contained in tag go1.9 ^go1.8 (tagged 2017-08-24) · 1136 in-scope commits

Type aliases. sync.Map. math/bits intrinsics. Inline-aware tracebacks and CallersFrames. Stack barriers removed. Concurrent runtime.GC(). Profile labels. Write-barrier insertion moved into SSA. Devirtualization. Groundwork for the concurrent backend. Monotonic time.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Memory management: GC and allocator (Go 1.0–1.17)

Noscan spans and spanClass, concurrent runtime.GC, treap for large spans, rationalised trigger, workbufs as manual spans.

  • Concurrent sweep and proportional sweep — Done: heap_live-driven proportional sweep (a5eb3dceaf, 9d36163c0b), sweepone tracking (44ed88a5a7), sweep allocation counting simplified (b50b728587), trace events cover the whole sweep loop (79c56addb6). Left open: nothing noted.
  • Decentralized GC state machine and mark termination simplification — Done: user-visible runtime.GC() and debug.FreeOSMemory now trigger a concurrent cycle (9ffbdabdb0, 786eb5b754, 3d58498fdb, 29fdbcfea3) instead of STW, with forced GCs tracked independently of gcMode; heap profile snapshotted in mark termination (eee85fc5a1, 1be3e76e76); finalizer queue not rescanned (f1ba75f8c5). Left open: STW GC mode remained as a separate code path.
  • GC pacer: trigger controller, assists and background utilisation — Done: trigger generalised and recomputed consistently (29be3f1999, 49a412a5b7, ee175afac2, 1c4f3c5ea0, a5eb3dceaf), no GC on SetGCPercent (227fff2ea4). Left open: soft/hard limit separation next release.
  • Stack scanning: conservative, precise by frames, stack barriers, hybrid barrier, async safe points — Done: rescan list removed (c5ebcd2c8a). Left open: g.gcscanvalid kept.
  • Hybrid write barrier and buffered write barrier — Done: write barriers eliminated from allocation/mark bitmaps (42c1214762), wbufptr removed (98da2d1f91), comment on compiler knowledge of writeBarrier (7e1832d06c). Left open: barrier still a normal call.
  • Precise heap scanning: type information, the heap bitmap and GC programs — Done: noscan spans (1a033b1a70, c44d031bf0, 8e25d4ccef). Left open: nothing noted.
  • Allocating from mark bits: allocBits, freeindex and ctz — Done: lock-free fast path for mark-bit allocation (2ef88f7fcf), simplified sweep allocation counting (b50b728587), markBits.clearMarkedNonAtomic removed (6aee6b895c), mcentral cache-line alignment (259d60995d), division avoided in gc (a4ee95c805). Left open: nothing noted.
  • Size classes, tiny allocator and mcache/mcentral — Done: spanClass, noscan segregation, sizeToClass removal (1a033b1a70, 295d160e01, 7ee43faf78). Left open: nothing noted.
  • Span lifecycle in mheap: free lists, treaps, first-fit and the page reclaimer — Done: treap for large spans (6e9ec14186); manual spans for workbufs (9cc883a466, 051809e352, dc0f0ab70f, 9741f0275c). Left open: nothing noted.
  • Heap address space: contiguous arena to sparse arenas — Done: arena bound fixes (4af6b81d41, e5a5c03f5b, 13ae3b3a8d, 780249eed4, 623e2c4603, 6c6f455f88). Left open: contiguous arena.
  • Mark work distribution: parfor, work buffers, gcWork and root jobs — Done: manually managed workbuf spans (9cc883a466, 051809e352), lfstack type (13ae271d5d), 489620d878 (drain local runq when a dedicated worker runs). Left open: nothing noted.
  • Runtime allocators for runtime metadata and the port to Go — Done: manually managed spans for workbufs and stacks (9cc883a466, 9741f0275c, dc0f0ab70f), malloc forbidden in scavenge (df6025bc0d). Left open: nothing noted.
  • Memory statistics and accounting — Done: user-visible ReadMemStats STW under 25 µs (4a7cf960c3). Left open: nothing noted.

Other changes
