Go 1.28

Part II · master 6c87434d24..4494c64f5a · 766 in-scope commits · unreleased, in development

mapsplitgroup by default. SSA package split into ssacompile and others. ARM64 SVE. The size-specialized-malloc flag is removed. Wyhash for small keys. Inlinable recover callers. Composite-literal type elision in progress. string(int) restricted. Linux perf profiles accepted for PGO.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Runtime: memory allocator and garbage collector (Go 1.18–1.28)

  • Green Tea: span-based marking with vector scan kernels — Done: the benchmark now cycles random object masks (27f1d81f7d). Left open: experiment flag not yet removed.
  • mallocgc decomposition and size-specialized malloc — Done: user-visible the GOEXPERIMENT was deleted, leaving the sizeSpecializedMallocEnabled constant (4a7645b730), plus ASAN dead-code cleanup (8a92448bc2). Left open: nothing noted.
  • Finalizers, runtime.AddCleanup and the cleanup queue — Done: cleanup argument layout uses the static abi.TypeFor[S], fixing interface arguments hidden as noscan on 32-bit (c456de74b8); a faster specials-list walk (Finalizer −1.2%, 1c72b3d2c1). Left open: nothing noted.
  • Weak pointers and the unique package — Done: unique.Make example (232c9e1160). Left open: nothing noted.
  • Object pinning (runtime.Pinner) — Done: atomic stores instead of RMW (91fa326dfe), skipping redundant bit updates (a69abce146), setting the specials bitmap only for the first special and skipping sweeper registration for swept spans (PinUnpinWithGC −32.5%, 7d93750c51), per-span unpin batching (d6eb7bd6ae), a shorter specials lookup (1c72b3d2c1), per-P pin-counter cache (3544f81e5d), and no system-stack switches, since pin bits no longer depend on the heap lock (3017a6ec16). Left open: nothing noted.
  • Sweeper termination and pacing — Done: replacing finishsweep_m’s sweep loop with a throw (5df35d3ce5) was reverted, because concurrent gcStarts can leave unswept spans (9684147f09). The reasons are now documented (8e0e1f7e99). Left open: #81957 remains open.
  • Stack and register root scanning — Done: register save blocks are no longer zeroed, since xRegSave overwrites them before publication (8f71bead49); clobberdead on loong64 (2c3e97ac68). Left open: nothing noted.
  • Address-space layout, tagged pointers and the mem.go layer — Done: openbsd/arm64 corrected to 39 address bits (3a5e97de8b). Left open: nothing noted.
  • Heap base address randomization — Done: the prefix mask was misaligned by up to 2 bits, so in ~75% of launches hints collapsed in pairs or quads; fixed (fb8616482c). Left open: nothing noted.

Scheduler and concurrency

From Runtime: scheduler, timers, channels, locks and synchronization (Go 1.18–1.28)

  • Timer rewrite: per-P timer heap, timer.lock, and GC-able synchronous timer channels — Done: user-visible time.Timer/Ticker copy detection (init bool replaced by self-pointer; f6ddbafcf0); delivered-time delta recomputed from a fresh clock just before send (277635b979); channel polling avoids duplicate timer checks and needless clock reads (713b754c97, 737d626d12); timers.verify stale check removed (eab6938192). Left open: nothing noted.
  • Scheduler core: spinning Ms, work conservation, stealing, STW interaction — Done: spinning Ms don’t commit to a runnext steal if a STW became pending during the sleep (a22b5bf6c5, #81657); async-preemption signals sent outside sched.lock in forEachP/stopTheWorldWithSema, avoiding a pile-up of Ms sleeping on sched.lock (b5bbf5b660); worldsema asserted in forEachPInternal (14c1cd3e46); safe-point requests re-checked in execute (BenchmarkAllocation -8.6%) (5336092116); preemption retry delay starts after each attempt and missed retries when pausing goroutines fixed (480af5e85a, d4fc38b7b6). Left open: nothing noted.
  • GOMAXPROCS container awareness and dynamic updates — Done: only the root of cgroup mounts is validated (f91a6faead). Left open: nothing noted.
  • testing/synctest bubbles — Done: synctest.IsInBubble made inlinable when no bubble exists, since WaitGroup.Add calls it (ace5a7527c). Left open: follow-up CL not to use sync.Pool within bubbles referenced.
  • Asynchronous preemption: extended register state — Done: AVX saved even without AVX2 (674806dda3); save blocks no longer zeroed (8f71bead49). Left open: nothing noted.
  • sync package API evolution — Done: Pool.Get only clears the private slot when non-nil: PoolGetEmpty/P=10 23.1ns -> 2.6ns (-88.8%) by avoiding cache-line contention with stealing Ps (d461d8f704). Left open: “sync: don’t use Pool from within synctest bubbles” in progress (referenced by ace5a7527c).
  • sync/atomic and runtime atomics — Done: riscv64 Xaddint64 return fix (3b98eddbcd). Left open: nothing noted.
  • Netpoller — Done: 32-bit eventfd type confusion fixed (b9ba134da6). Left open: nothing noted.

Other changes

  • Misc internal — leave instruction on AMD64 reverted (56d7cfd457, ebdf81fda7); align128 marker (c2dcde178d); plan9 low-res timer (d2d6d44095); caller frame pointer in mstart1 (2c081ba80d); pinning avoids stack switches and caches counters per P (3017a6ec16, 3544f81e5d).

Data structures and type metadata

From Runtime: maps, built-in data structures, hashing, randomness and type metadata (Go 1.18–1.28)

  • Swiss-table maps (GOEXPERIMENT=swissmap → only implementation) — Done: mapaccess2 inlined into mapaccess1 by raising the inline budget, because the wrapper cost showed in synthetic benchmarks (defa1f0155; ideal of inlining mapaccess1 at the call site judged hard since calls are introduced in walk, after inlining). Small-key hashing switched from AES to wyhash below MinAeshashSize (c9e4a2aa07, b751a977cb; see hashing thread). Left open: latency-vs-throughput cutoff for arm64 (go.dev/issue/80970) noted in b751a977cb.
  • Map hashing and hash functions (memhash, aeshash, fallback hash) — Done: UseAeshash replaced by a tunable MinAeshashSize: very small keys use wyhash because AES SIMD “does not like being used for one-offs”: cutoff 8 bytes on Zen 4 (MapGroupBy, HashInt64Speed -10%, MapAccessMiss/int64/len=65536 -10.9%) (c9e4a2aa07), 16 bytes on Apple M1 Max (b751a977cb: Hash5 -41%, MapGroupBy/int64 -65%). Interface hashing now folds the dynamic type’s compiler typehash in so int64(0) and uint64(0) in interfaces no longer collide (40e7643c46). Left open: cutoffs for other microarchitectures (Intel steppings) are said to be easy follow-ups; latency cutoff of 192 on arm64 unexplored (issue 80970).
  • Compiler-generated equality/hash functions and type descriptor emission (reflectdata) — Done: subroutine-based eq/hash for large types (16516099d7), noalg/alg dedup and its fixes (8fc7e76411, 925ef8c02c, f3e4f788ed, 4400f9ad36), writeType symbol reuse (7ea76879d2), cleanup of curfunc naming in reflectdata (d5f5390d0d). Left open: signature names remain large (“The signatures themselves (and their names) are still pretty big”, 16516099d7).
  • reflect implementation: performance, allocation and escape behaviour — Done: method Value representation reworked: previously (receiver, method index, special flag) with lazy conversion to a func Value on Interface/Convert, which flowed the Value to a heap methodValue and made those operations escape their receiver; now the func Value is created eagerly, and the receiver+index are stored in the methodValue closure so Call keeps its fast path (creating a method Value costs an allocation, Call unchanged) (3ebc191975, with c78af9ddc8 improving Value.Set escape); MethodByName avoids building a full Method via FuncOf (1a1b710b4c, motivated by text/template, e.g. Gitea’s ~4,700 ctx.Locale.Tr calls), a795dd2918; embedded reflect types extracted before use (cff61723f3); SetIterKey/Value temporaries without map flags (d9377b86ee). Left open: nothing noted.
  • memmove / memclr / memequal / internal/bytealg assembly optimisation — Done: arm64 indexbyte algorithm (5afcc450ee), compare 32 bytes per iteration and NEON for large inputs (e24c7a6508, ce608609c1), small-size memequal restructure (916488f43a), loong64 LSX for 33..64-byte memmove (55d79d1e8a), SIMD arm64 memmove (91aa6bb390) reverted a month later (dac9fe5ea9, named-register cleanup b6c48d70ca retained). Left open: arm64 SIMD memmove needs redo.

  • Prove pass and bounds-check elimination: from poset relations to a dense limit table, topo-sorted walk, and division-aware proofs — Done:
    • Constant-delta additions (8ee6c488c2). The induction-variable minimum is visible in its block (6547138e2b).
    • Signed↔︎unsigned limit propagation (13a7b71d85). Unused poset unsigned machinery removed (0c0dacdf0b).
