Go 1.4

Part II · commits first contained in tag go1.4 ^go1.3 (tagged 2014-12-11) · 644 in-scope commits

Most of the runtime converted from C to Go (scheduler, channels, maps, panics, signals). Stack copying is the only mechanism, with 2 KB minimum stacks. The compiler emits write barriers. atomic.Value. Android.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Memory management: GC and allocator (Go 1.0–1.17)

Allocator and collector prepared for Go: free removed, stack allocator split out, byte-array bitmap, more parallelism; GC still stop-the-world.

  • Stop-the-world mark-sweep, then the parallel collector — Done: parallelism pass (44106a0880, 192bccbf33, f6f2f77142, 0c32bd6262, 98bebcc90a parfor in Go, aac7f1a0d6 markallocated in Go, c46bcd4d13 finalizer goroutine in Go); stack shrinking delayed until GC is done to avoid the GC seeing freed stacks through SudoG.elem (91e8554b8b); invalid pointers into the GC arena crash (11e53e46a6); MemStats.PauseEnd (46af78915a); go1.4 gctrace shows goroutine count (ed7db89b90). Left open: all of it still stop-the-world, with mark termination doing all marking; the power64 port disabled GC (9b88857f751.5, in the dev.power64 branch landed in 1.5).
  • Concurrent sweep and proportional sweep — Done: sweepgen set before span state (3590d9ce69); transfer cache so a swept span does not bounce between mcentral/mheap locks (e0df11d57e: the previous dance was lock mcentral, remove, unlock, unmark, lock mheap, insert, unlock, lock mcentral). Left open: nothing noted.
  • Concurrent mark: write barriers and the dev.garbage collector — Done: compiler-inserted write-barrier call sites (a no-op barrier; b035e973151.5’s message refers to barriers inserted “for Go 1.4”). Left open: collection still STW.
  • Stack scanning: conservative, precise by frames, stack barriers, hybrid barrier, async safe points — Done: conservative scanning of stacks removed for Go frames (d208361cde), shrunk stacks freed only after GC (91e8554b8b, d57056ba261.5 later), parallel shrink (192bccbf33). Left open: stack rescan in STW.
  • Precise heap scanning: type information, the heap bitmap and GC programs — Done: byte-array bitmap (ff3fa1b32d), unrolled mask cache (b91223edd1), backward scan removal (03f2189a1b), bitmap corruption fix (5bfe8adee5), type mandatory for scannable allocation (fb44fb6cb7). Left open: 4 bits per word and boundary bits.
  • Size classes, tiny allocator and mcache/mcentral — Done: free removed (cecca43804), transfer cache (e0df11d57e), alloc counted for tiny allocs for testing.AllocsPerRun (e19d8a47d1). Left open: nothing noted.
  • Span lifecycle in mheap: free lists, treaps, first-fit and the page reclaimer — Done: mheap not locked on user goroutine (e91704af27: the code under lock could grow the stack), allspans races (7f223e3b3b). Left open: nothing noted.
  • Heap address space: contiguous arena to sparse arenas — Done: heap growth by 64K (0622e13b4d); mincore in addrspace_free (0e1b6bb5471.3). Left open: nothing noted.
  • Finalizers and span specials — Done: finalizer thread in Go (c46bcd4d13). Left open: nothing noted.
  • Mark work distribution: parfor, work buffers, gcWork and root jobs — Done: parfor converted to Go (98bebcc90a), workbuf cache (f6f2f77142, ac9218f5f0), parfor untyped allocation removed (fc46931442). Left open: nothing noted.
  • Runtime allocators for runtime metadata and the port to Go — Done: stack allocator (7c13860cd0), stack orders raised to 4 in 1.5 (5aae246f1e1.5), sysAlloc nosplit (99a08262af). Left open: C-written malloc.
  • Memory statistics and accounting — Done: PauseEnd (46af78915a), stats fixes (30ef2c7deb, 266d350f5e, 01a7d39df1), tiny allocs counted (e19d8a47d1), gctrace goroutine count (ed7db89b90). Left open: nothing noted.

Other changes
