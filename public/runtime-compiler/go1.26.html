Go 1.26

Part II · master 2696a11a97..83c44ec032 · 1082 in-scope commits

Green Tea by default. SIMD (archsimd, amd64) lands behind an experiment. Old maps deleted. move2heap stack-allocated appends. panicBounds. Duff’s device removed. s390x register ABI. runtime/secret, heap-base randomization and freegc experiments. Goroutine-leak profile experiment. new(expr). Size-specialized malloc: on in master, off in the release.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Runtime: memory allocator and garbage collector (Go 1.18–1.28)

  • Green Tea: span-based marking with vector scan kernels — Done: user-visible enabled by default except on loong64, where the compiler crashed on the Green Tea code (7fbf54bfeb); loong64 enabled later in the cycle (c53cb642de). The AVX-512 kernels were imported (889ab74169) and wired into scanSpan, giving “an extra 15-20%” on dense spans (5d040df092). scanobject was duplicated per mode to tell them apart in profiles (41b429881a, 1aa154621d). The global span queue was replaced by spanSPMC rings and work-stealing (d7a38adf4c); gcMarkWorkAvailable was split into a termination condition and a worker-spawn heuristic (fde10c4ce7). Follow-up fixes for spanSPMC: an unbounded loop when more than 64 live rings existed (f3312124c2), rings leaked on P destroy (3ee761739b, 7dd54e1fd7), list type (046dce0e54), lock rank (052c192a4c), and removal of the unused mspan.scanIdx (2baa1d1762). Kernel fixes and tuning: cache-size probing (adbf59525c), a size-class check (ff2ebf69c4), a register destination for VPCOMPRESSQ (−70% on Zen 4, 041f564b3e), an AVX-512 filterNil (+40% throughput, a9704f89ea), and VZEROUPPER (0d71bd57c9). A Go-simd-package kernel set (da92168ec8, −19% ns on the scan benchmark) was reverted for naming and merge conflicts with a plan to “do it again” (0c69e77343). Left open: freeSomeSpanSPMCs batching was dropped, “may want to revisit … for very high GOMAXPROCS” (f3312124c2). The simd-package kernels have not been relanded at HEAD, and scan_go.go still carries a TODO.
  • Heap bitmap rewrite and allocation headers — Done: invariant work hoisted out of heapBitsSmallForAddrInline in Green Tea’s sparse scan loop (65c09eafdf). Left open: nothing noted.
  • mallocgc decomposition and size-specialized malloc — Done: user-visible GOEXPERIMENT=sizespecializedmalloc added (60c1ee9183) and enabled by default (a7917eed70). Generator, templates and tables (a69395eab2, 411c250d64); the size-class generator moved into _mkmalloc (f37d75472d); direct compiler calls (19a30ea3f2); valgrind support (c54dc1418b); generator polish (21ebed0ac0, 2947cb0469, e2fef50def); an explicit nil check in heapSetTypeSmallHeader to avoid read-then-write page faults (tile38 at GOMAXPROCS=192: +9.6% ops/s, p99 −15%, 3032894e04). Left open: “I still need to investigate heapsampling.go” (411c250d64).
  • Scavenger redesign — Done: on Linux, memory released with MADV_DONTNEED is known to be zero, so software zeroing is skipped on reuse (27937289dc); a duplicate scavengeIndex.sysGrow call removed (4fca79833f). Left open: nothing noted.
  • Finalizers, runtime.AddCleanup and the cleanup queue — Done: user-visible panics when ptr == arg or when the cleanup closure captures ptr (06412288cf, eb63ef9d66); separate argument storage (−16.7% ns, −33% B/op, 1bb1f2bf0c); benchmark (9fd2e44439); /gc/cleanups/… and /gc/finalizers/… queue metrics (a4d99770c0); test log (43ebed88cc). Left open: nothing noted.
  • Weak pointers and the unique package — Done: weak handles padded to 16 bytes so they bypass the tiny allocator and cannot leak neighbors (80c91eedbb); canon map fixes (ffa882059c, 47bf8f073e); test (a33bbf1988). Left open: “We could potentially do better by using the 8 byte noscan size class” (80c91eedbb).
  • Object pinning (runtime.Pinner) — Done: documentation (856238615d, 76345533f7). Left open: nothing noted.
  • Memory arenas experiment — Done: assist credit for arena chunks deducted only during GC, restoring behavior lost in the 1.24 malloc split (d79405a344); test skips (1a03d0db3f, 96e142ba2b). Left open: nothing noted.
  • runtime.freegc: compiler-directed explicit freeing — Done: user-visible freegc with reuse lists and clobberfree (fecfcaa4f6), an assist-credit test (120f1874ef), size-specialized noscan reuse (50128a2154), the experiment renamed to runtimefreegc and off for 1.26 (5a347b775e), and compiler alias analysis with growsliceNoAlias (4879151d1d, compiler area). Left open: freegc “throws if noscan is false (support for which is implemented in a later CL)”. The specialized-malloc path disables pointerful freeing via a TODO, and clobberfree=2 (mprotect) is described as a later experimental CL (fecfcaa4f6, 50128a2154). None of these has landed at HEAD.
  • Mark worker scheduling and GC work queues — Done: worker selection during start-the-world (829779f4fe, a18aff8057); atomic p.gcFractionalMarkTime (d3aeba1670). Left open: if fewer than 25% of Ps are idle, some user Ps still turn into dedicated workers, and stack-scan resumes still migrate goroutines (a18aff8057).
  • Stack and register root scanning — Done: stack shrinking disabled whenever a goroutine waits for suspendG (tracer, mutex profiling), instead of trying to be shrink-safe (bd07fafb0a). Left open: nothing noted.
  • Address-space layout, tagged pointers and the mem.go layer — Done: one more address bit for tagged pointers for amd64-on-arm64 emulation (2a7f1d47b0); riscv64 sv39/48/57 detection, cutting startup from ~85 mmaps/66 munmaps to 22/0 on sv39 (dae9e456ae); gccgo build tags (643f80a11f). Left open: nothing noted.
  • Linear-memory heaps (Wasm and sbrk platforms) — Done: user-visible Wasm heap arena and page-chunk size reduced to 512 KiB; hello-world drops from 8 MB to <3 MB linear memory (53009b26dd). sbrk mem.go switches to the system stack to avoid memlock self-deadlock (11d5484190). Left open: nothing noted.
  • Heap base address randomization — Done: user-visible randomization (6669aa3b14), on by default (72ba117bda), disabled with ASAN/MSAN (77aac7bb75), test fix (465b85eb76). Left open: nothing noted.

Other changes

  • runtime/secret allocation size internal — the secret special records the object size so memclr does not overwrite neighbors (b8c4cc63e7).
  • hexdumper internal — configurable hexdump (any word size, ASCII column, multi-annotation marks) that replaces hexdumpWords output in the runtime’s existing dumps, ahead of debuglog integration (e912618bd2).
  • GC-based goroutine leak detection user-visible — goroutine leak profile computed by the garbage collector, behind GOEXPERIMENT=goroutineleakprofile (8c68a1c1ab, diag/sched area).

Scheduler and concurrency

From Runtime: scheduler, timers, channels, locks and synchronization (Go 1.18–1.28)

  • Timer rewrite: per-P timer heap, timer.lock, and GC-able synchronous timer channels — Done: Timer.Reset(0) inside a synctest bubble no longer deadlocks on sendLock being taken twice (385dc33250). Left open: nothing noted.
  • Scheduler core: spinning Ms, work conservation, stealing, STW interaction — Done: P-to-M affinity across STW: sched.midle made doubly linked so a specific M can be pulled out, Ps restart on their previous M and STW preemption via goschedImpl keeps the G on its P (2263d4aabd, 4ebf295b0b; TestTraceSTW error rate 99.8% -> 1.9%); GC mark workers chosen in procresize during start-the-world to avoid sequential wakeps (a18aff8057); steal path avoids the 3us usleep before taking runnext when the victim is in a syscall, now that such Ps stay _Prunning (d55ecea9e5); debug mode extending _Grunning-without-P windows (7a8d0b5d53). Left open: “best effort” affinity; spinning M can still steal from a slow-restarting P.
  • Syscall path: eliminating _Psyscall, _Gdeadextra, and goroutine states — Done: the above commits, plus user-visible runtime/metrics for goroutine scheduling states, total goroutines created and thread counts (13df972f68, ab8121a407, 78a3968c2c). Left open: “_Grunning-without-P” debugging only via an env debug mode (7a8d0b5d53).
  • GOMAXPROCS container awareness and dynamic updates — Done: cgroup v1 non-root mount points handled, path validation and fuzz tests (c2af9f14b4, cead111a77, 67851547d8). Left open: nothing noted.
  • testing/synctest bubbles — Done: all bubble violations are fatal panics (so e.g. context cannot be left inconsistent by a recoverable panic) (a8564bd412); synctest GOEXPERIMENT removed (4c0fd3a2b4); Reset(0) hang fix (385dc33250); specials lock (5dcedd6550). Left open: nothing noted.
  • Asynchronous preemption: extended register state — Done: scalar registers saved off-stack (af0c4fe2ca), AVX2/AVX-512 (55d961b202), arm64 Neon (955a5a0dc5), loong64 fcc/lasx/lsx (bd885401d5, 99cf4d671c), cherry-picked from dev.simd. Left open: GC scanning of that state.
  • sync package API evolution — Done: WaitGroup.Go no longer calls Done when f panics (95a0e5adc1); race annotations kept when panicking (8f74f9daf4). Left open: nothing noted.
  • Goroutine lifecycle and identity — Done: user-visible goroutine leak profile behind GOEXPERIMENT=goroutineleakprofile (8c68a1c1ab); DIT inheritance (af14f67911). Left open: experiment only.

Other changes

  • GOTRACEBACK for user panics internal — 02d1f3a06b.
  • Misc internal — recover detection (7b50024330); eventfd errno (d3be949ada); debug settings initialised earlier (300d9d2714); p.destroy assert (6469954203); castogscanstatus no panic (b5353fd90a); preemptPark dropg after trace (6455afbc6f); pMask dedupe (69e74b0aac); NetBSD sysmon workaround dropped (52b6d7f67a); internal/cpu inline (fe42628dae); loong64 CAS jump (d4b17f5869); secret goroutine behaviour restored to proposal (63fced531c); dev.simd merge commits (426cf36b4d, 9eeb1e7a9a, 574854fd86, 0710cce6eb, a8669c78f5); panic output priority (89dee70484); openbsd check (87e72769fa); internal/itoa removal (49c1da474d); fips WithoutEnforcement (86bbea0cfa).

Data structures and type metadata

Left open: nothing noted.
  • Map hashing and hash functions (memhash, aeshash, fallback hash) — Done: 32-bit hash on wasm (a26f860fa4). Left open: nothing noted.
  • Compiler-generated equality/hash functions and type descriptor emission (reflectdata) — Done: ptrmask no longer cleared in fillptrmask (e0807ba470), type-load folding (5b218461f9), TypeFor made inlineable (dc960d0bfe; also forces TypeLinksym in writeType for non-shape types so later lookups see the symbol).   • reflect implementation: performance, allocation and escape behaviour — Done: user-visible iterator equivalents Type.Fields/Methods/Ins/Outs style (e8fdfeb72b); TypeAssert[I] allocates only on success (684e8d3363); TypeFor fully inlineable (dc960d0bfe); zero-sized fields of direct structs fix attempted then reverted (b3388569a1, caf9fc3ccd).   • memmove / memclr / memequal / internal/bytealg assembly optimisation — Done: RISC-V vector indexbyte, equal, compare (3406a617d9, 75ea2d05c0, d83b16fcb8), mips64x/s390x memclr (b6cf1d94dc, a8edd99479), loong64 Index (dd3abf6bc5), arm64 DC ZVA mnemonic instead of WORD (e7351c03c8), benchmark for small sizes (e84ed38641). Left open: nothing noted.
  • Runtime randomness: fastrand, chacha8rand and math/rand/v2 — Done: riscv64 vector implementation (6f04a92be3), loong64 instruction mnemonics (5defe8ebb3, 01c29d1f0b). Left open: nothing noted.
  • Concurrent hash-trie map (internal/sync.HashTrieMap) — Done: warning about incorrect unsafe usage documented (1718828c81). Left open: nothing noted.
