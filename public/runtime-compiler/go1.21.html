Go 1.21

Part II · master 83f8688915..21ff9be0eb · 967 in-scope commits

Inference rewrite plus min/max/clear. Unified IR is the only frontend. abi.Type unification. Unwinder iterator replaces gentraceback. PGO devirtualization, and the compiler itself is built with PGO. PanicNilError. Pinner. wasip1. Tracer groundwork and FP unwinding.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Runtime: memory allocator and garbage collector (Go 1.18–1.28)

  • GC pacer redesign — Done: cons/mark smoothing became the max over 5 cycles, biased against assists (b513bd808f, comment fix 600b982df9). Left open: after an application becomes less GC-active, the stale cons/mark persists for 5 cycles. The commit accepts this (b513bd808f).
  • Soft memory limit and GC CPU limiter — Done: user-visible the limit is initialized in mallocinit, so early allocations do not scavenge needlessly (96e8e62821). Headroom became proportional (3%) to stop GOGC=off programs from scavenging on most allocations (e97bd776f9). Eager-scavenge details were added to scavtrace (a3e90dc377). The go119MemoryLimitSupport flag was removed (79edd1d19d), a lost idle-time flush was fixed (24617a068c), and a /gc/gomemlimit:bytes metric was added (2544b1051e). Left open: “This choice is still somewhat arbitrary … perhaps worth revisiting” (e97bd776f9).
  • Scavenger redesign — Done: idle Ps’ page caches flushed at the end of each GC so the scavenger can see them (8d68b388d4); index initialization and minHeapIdx restored (8588a3fa08, 15c1276246); eager-scavenge statistics in scavtrace (a3e90dc377); density tracking (huge-page thread). Left open: nothing noted.
  • Transparent huge page management — Done: explicit policy with 96% density and 1-GC-cycle hysteresis (8fa9e3beee), sysNoHugePage (84eaceaba7) with a page-alignment check (ada0eec827), and metadata huge pages only for large heaps (1f9d80e331). Left open: “The main risk here is churn” (8fa9e3beee).
  • Finalizers, runtime.AddCleanup and the cleanup queue — Done: test portability only (fbf14ae166). Left open: nothing noted.
  • Object pinning (runtime.Pinner) — Done: user-visible the Pinner API (251daf46fb), gcBits-based state (697644070c), ref preallocation and P cache (4bb38fe458, 0adcc5ace8, benchmarks 94c75232fb, 5d68121628), lock-rank edges (78df00dd6f, 807cce479f), and docs (c7b2f6494c). Alongside: heapObjectsCanMove() (always false) for go4.org/unsafe/assume-no-moving-gc, so that package stops breaking on each release (055c186f53, 789701e93a). Left open: nothing noted.
  • Memory arenas experiment — Done: user-visible reflect.ArenaNew changed to take T and return *T, a breaking change (2b0ff4b629). Left open: nothing noted.
  • Mark worker scheduling and GC work queues — Done: work.full/work.empty padded against false sharing (gRPC +8%, DeathStarBench +9.7%, bdc5533f39); duplicate work.full check removed (9411075748). Left open: nothing noted.
  • Sweeper termination and pacing — Done: overflow in the sweep-assist delta could pin all allocators in sweeping until termination; fixed (a7b75972f2). Left open: nothing noted.
  • Address-space layout, tagged pointers and the mem.go layer — Done: lfstack→taggedPointer (d959dd97b1); fallback to mmap when madvise is compiled out of Linux (5ffdc1f15c). Left open: nothing noted.
  • Linear-memory heaps (Wasm and sbrk platforms) — Done: Wasm reuses blocks freed via sysFreeOS, sharing Plan 9’s sbrk strategy (dac514ea37). Left open: nothing noted.

Other changes

  • Write-barrier buffer generalized for batching internal — the runtime no longer requires pointers in pairs and checks overflow first (d3daeb5267); the compiler batches barriered writes into gcWriteBarrier1..8 buffer slots (21d82e6ac8, compiler area). user-visible GODEBUG=cgocheck=2 became GOEXPERIMENT=cgocheck2 to enable these barrier optimizations (55044288ad).
  • reflect typedmemmovepartial removed internal — unused (df6396fc22).
  • Tracer state refactors at GC call sites internal — traceEnabled() and per-P trace state (8992bb19ad, b7e767b022), diag area.
