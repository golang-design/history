Go 1.0 (pre-release history 2008–2012)

Part II · commits first contained in tag go1 (tagged 2012-03-28) · 3138 in-scope commits

Everything up to the go1 tag, 2008–2012. 6g/8g/5g with the C frontend gc, Plan 9-derived C compilers and assemblers. Segmented stacks. A tcmalloc-style allocator with a stop-the-world mark-sweep collector. A global-lock M:N scheduler. hashmap.c and the 2009 and 2011 reflect redesigns. Escape analysis and a first inliner. ELF/Mach-O/PE linkers with DWARF and dead-code elimination. runtime/pprof.

Each area lists the stage every thread reached in this release (with what was left open afterwards), then changes that are not part of a thread. Thread names link to the full thread on its topic page.

Memory management

From Memory management: GC and allocator (Go 1.0–1.17)

Everything up to the go1 tag: tcmalloc-style allocator (2008-12), stop-the-world mark-sweep (2009-01), finalizers, a faster collector in 2011 (1e063b32cd), helper threads, memory release to the OS (5c598d3c9f); threads "Stop-the-world mark-sweep…", "Size classes…", "Scavenger", "Finalizers".

  • Stop-the-world mark-sweep, then the parallel collector — Done:
    • 2008-2009: allocator and first collector (e29ce175ed, 1ce17918e3, 9f726c2c8b); heap map split from malloc for 64-bit (80f4ab47ee); a bug in the size-class waste check that produced far too many classes fixed (c1e748bd2e); stacks no longer malloc’d during GC (8c357ce269).
    • 2010: finalizers merged into package runtime (33e396a4a7); sweep and GC specialisation (f25586a306, fb94be55dc, 22a7f2a14d drops MHeapMapCache); GC clocked on bytes allocated (8ddd6c4181); memory profiling hook (596c16e045).
    • 2011: simpler dense heap map in bss (4608feb18b); faster allocator and collector (1e063b32cd); standard-sized stacks off the central FixAlloc (c9152a8568); helper threads for parallel marking (a5f064a3e1, 8219cc9af8); per-M MemStats caches (66d5c9b1e9, 27753ff108).
    • 2012: ReadMemStats replaces UpdateMemStats (842c906e2e); 32-bit fallback when the 64-bit reservation fails (d37a8b73c5). Left open: GC was stop-the-world and single-threaded in the go1 tag; stack and heap scanning were conservative.
  • Span lifecycle in mheap: free lists, treaps, first-fit and the page reclaimer — Done: span list-based heap with coalescing (9f726c2c8b allspans), release unused memory (5c598d3c9f, see scavenger). Left open: nothing noted.
  • Scavenger: returning memory to the OS — Done: user-visible periodic release of unused memory with madvise (5c598d3c9f), HeapIdle tracking (33d00fae30). Left open: fixed 2/5-minute thresholds.
  • Heap address space: contiguous arena to sparse arenas — Done: dense heap map (4608feb18b), >512 MB 32-bit (70b0de8e98), alignment checks (48535ae3f1), 64→32-bit fallback (d37a8b73c5, 073aeff785, 3dcedb620c). Left open: fixed contiguous reservation.
  • Finalizers and span specials — Done: finalizers, table, single goroutine (33e396a4a7, f25586a306, acfd7b8d12, 4e28cfe970, 24c58174b2, 69a91663d2). Left open: a second mark+sweep pass for finalizers existed until 4e28cfe970.
  • Memory statistics and accounting — Done: per-M caches (66d5c9b1e9), HeapIdle (33d00fae30), ReadMemStats (842c906e2e), mallocs and sampling fixes (ad35cea762, 1135fc3978). Left open: nothing noted.
